## 1. 用户的策略（2026-11-26 核查，只读，没有改动）

| 文件 | 内容 |
| --- | --- |
| `policy.onnx`（4.1 MB） | 输入 `obs_history` [N, 235]，输出 `actions` [N, 12]；opset 18；约 101 万个参数。**带完整的元数据**：<br>· 关节名、默认关节角、动作缩放；<br>· 控制周期 0.02 s；<br>· 观测布局：47 维 × 5 帧历史，最旧的在前，重置时重复初始帧；<br>· 观测项：角速度、投影重力、关节位置偏移、关节速度、上一次动作、速度指令（机身 xy、世界偏航）、步态相位 sin / cos（周期 0.6 s，指令小于 0.1 时为 0）；<br>· 归一化在图内 |
| `model_15000.pt`、`model_10000.pt`（各 32 MB） | **训练检查点**（参数字典与训练配置，格式 `supermimic_moe_velocity_v1`），不是 TorchScript；没有训练代码就无法单独运行；与 ONNX 用同一个 `spec_hash` 对应 |
| `task_config.json`、`params/*.yaml` | 训练配置：PD 刚度（hip 20、thigh 20、calf 40）与阻尼（1、1、2）、力矩上限、电枢 0.01、物理步长 0.005 s、降频 4 |
| ONNX 用到的算子 | Gemm、Elu、Softmax、Conv、ReduceL2、ReduceSum、Clip、Sub、Div、Mul、Reshape、Slice、Concat、Expand、Shape、Squeeze、Unsqueeze、Constant |

**结论：**
- ONNX 的元数据加上旁边的训练配置，足以**完全自动配置**；
- 训练检查点由自动配置识别：同目录下有同一 `spec_hash` 的 ONNX 时直接使用它；没有时说明需要用训练代码导出。

## 2. 推理组件（库文件）的管理（M4-10a）

| 项 | 做法 |
| --- | --- |
| 组件清单 | `assets/components/components.json`：每个组件的标识、显示名、版本、大小、许可、下载地址、校验值、安装后的文件 |
| 第一个组件 | **ONNX Runtime 1.32.0（CPU）**，来自 NuGet 上 Microsoft 签名的包（184 MB，校验 NuGet 公布的 SHA-512 与我们记录的 sha256；只解出 `libonnxruntime.so`，约 35 MB，与许可文件）。<br>2026-11-26 核查：GitHub 上微软的发布页已返回 404，第三方“镜像”的同名文件 sha256 互不一致，因此只用 NuGet |
| 安装位置 | 资源库目录下的 `components/<标识>/`（与资源库位置的设置一起，不写系统目录，不需要 root） |
| 客户端 | 运行或导入需要某个组件的策略时：<br>· 组件不在时弹窗说明“需要下载 ONNX Runtime（184 MB，许可 MIT）”，可选“下载并安装”（进度条、可取消）或“稍后”；<br>· 下载失败或没有网络时给出警告，并给出手动安装的方法：在有网络的机器上下载给出的地址，再用“从文件安装…”选这个文件；<br>· 偏好设置中新增“组件”页：列出已安装与可安装的组件、大小、版本，可以删除、重新校验 |
| 命令行 | `terra_headless --install-component onnxruntime-cpu [--from 文件]`；没有组件时 `--policy` 给出同样的提示并返回错误码 |
| 加载 | 运行时 `dlopen` 组件中的库；构建不依赖它（仓库只带 C API 头文件 `third_party/onnxruntime/include`，MIT） |
| 以后 | ONNX Runtime GPU（CUDA）、其他厂商的执行提供程序作为新的组件加入清单；D-111 的“内置推理核心”作为可选后端保留 |

**PyTorch（`.pt` 用）：**
- TorchScript 的 `.pt` 在导入时转换为 ONNX，转换用机器上已有的 PyTorch（调用 Python，与 xacro 的方式相同）；
- 没有 PyTorch 时，提示安装命令，也可以由客户端在资源库目录下建一个独立的 Python 环境，代为安装 CPU 版的 PyTorch（带进度；约 200 MB）；
- 转换后的 ONNX 记下来源与 sha256，之后不再需要 PyTorch。

## 3. 策略的运行（M4-10a）

- **说明文件** `*.terra-policy.json`（第一版第 2 节的格式，补上历史帧、相位的写法与模型元数据的来源）：由自动配置生成，用户一般不需要手写。
- **后端接口**与注册表（第一版第 3 节）；本步注册：
  - `onnxruntime-cpu`：单线程、确定性计算选项，同一机器上逐位可复现；
  - `linear`：测试与调试用。
- **策略控制器**（第一版第 4 节）：
  - 降频（控制周期 ÷ 物理步长）；
  - 历史帧（最旧的在前，重置时重复初始帧）；
  - 相位时钟；
  - `positionPd` 动作：每步按 kp、kd 算力矩，截断到力矩上限；
  - 速度指令：来自界面、键盘或 ROS2 的 `/cmd_vel`。
- **观测从带噪声的读数取**（用户的决定）：
  - 角速度与重力方向取 IMU（带 M4-09 的噪声）；
  - 关节位置与速度取快照（M4-09 没有关节编码器的噪声，以后可以加）。
- **Headless：**`--policy <说明文件> [--command vx,vy,yaw]`。
- **查看器：**“仿真 → 运行策略…”，策略运行时视口上方出现速度指令的小面板（键盘 W/A/S/D、Q/E 或滑块）；开启 ROS2 时 `/cmd_vel` 同样生效。

**验收（用用户的 Go2 策略）：**
- 在 Go2 低层控制场景（力矩执行器、机身 IMU）中站立 10 s 不倒；
- 前进指令 0.5 m/s 时 10 s 内平均速度在 0.3～0.7 m/s（阈值看第一次结果再冻结），转向指令时偏航角速度方向正确；
- 同一机器上两次运行逐位相同；实验记录复现逐位相同。

**注意：**
- 训练时的物理步长是 0.005 s（mjlab，MuJoCo 3.11），Terra 的 Go2 是 0.002 s（MuJoCo 4.0.1）；
- 训练中有域随机化（摩擦、质心、编码器偏置）；
- sim2sim 的差别会影响表现。第一次结果出来后，按实际表现决定阈值，并记录差别。

## 4. 策略导入向导与自动配置（M4-10b）

- **入口：**菜单“策略 → 导入策略…”，或把 `.onnx` / `.pt` 拖进窗口；
- **用户只做两件事：**选策略文件；选机器人（资源库中的场景卡片，按关节名自动推荐匹配的场景）。
- **自动配置的来源**（按顺序）：
  1. ONNX 的元数据（已知格式：`supermimic_moe_velocity_policy_v1`；以后可注册新的格式解析器，与导出器相同的方式）；
  2. 同目录或上级目录中的训练配置（`task_config.json`、`env.yaml`、`deploy.yaml`、宇树 `unitree_rl_gym` 的 `configs/*.yaml`）；
  3. 都没有时，向导列出无法确定的项让用户填写。
- **自动完成的配置：**
  - 关节名对应（`FL_hip_joint` ↔ `go2/FL_hip_joint`）；
  - 默认姿态、动作缩放、PD 增益（按关节组）；
  - 力矩上限、控制周期与降频；
  - 观测项与历史帧；
  - 需要力矩执行器时，生成一个开启 `torqueActuators` 的场景副本。
- **结果：**
  - 生成 `*.terra-policy.json`，与模型一起登记到资源库（资产新类型“策略”，关联机器人与场景）；
  - 场景卡片上出现“策略”标签，单击即可运行。
- **`.pt`：**
  - TorchScript → 转为 ONNX（第 2 节）；
  - 训练检查点 → 找同一 `spec_hash` 的 ONNX，没有时说明原因与导出方法。
