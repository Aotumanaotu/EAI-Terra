# M4-08d ROS2 面板与显示配置：实现报告

> 状态：**通过**（2026-11-25，第五次基线运行）。设计见 [M4-08d 设计稿](M4-08d-ros2-panel-design.md)（评审通过；用户要求为以后的导出格式与参数留出余地，见设计稿 4.1 节）。
> 验证脚本：`bash scripts/verify/m4_08d.sh`。

## 1. 用户看到的变化

| 位置 | 变化 |
| --- | --- |
| 窗口 → ROS2 | 话题表：类型、发布 / 订阅数、QoS（悬停）、频率与带宽（打开该话题后统计）；节点分页。行尾按钮一键打开：消息、图像（Image 与 CompressedImage）、TF 树、曲线（Imu、Odometry、Twist、std_msgs 数值有预设字段） |
| 消息窗口 | 任意类型逐字段展开（宇树 LowState 等第三方消息只要已 source 即可）；长数组分页（每页 100 项）；数值字段旁的 **+** 加入曲线 |
| 曲线窗口 | 多条曲线，可混合 ROS2 与仿真来源；时长 5～60 秒；接收时间 / 消息头时间；暂停；图例显示最新值与问题（字段不存在、下标越界） |
| 图像窗口 | rgb8、bgr8、rgba8、bgra8、mono8、mono16、16UC1（毫米 → 米）、32FC1；PNG / JPEG 压缩图像；深度伪彩色或灰度；分辨率、帧率与延迟 |
| TF 树 | 父子关系、平移、欧拉角；静态变换标注；超过 1 秒没更新标黄 |
| 传感器面板 | IMU 下方“弹出为曲线窗口”（仿真来源，随显示配置保存） |
| 窗口 → 显示配置 | 本场景的各份配置（点一下切换）、保存、另存为、导出、导入、关闭全部窗口；ROS2 面板顶部有同样的工具条 |
| 打开场景 | 自动恢复该场景上次使用的显示配置（窗口、话题、字段、位置与大小） |
| 资源库 | 场景卡片显示“N 份显示配置”，右键“以显示配置打开” |
| 导出弹窗 | 格式来自导出器注册表（本步 `.terviz`、`.rviz`），可多选；参数按清单自动生成（`.rviz`：固定坐标系、网格、视距、帧率）；列出不能导出的部分 |
| 没有 ROS2 | “窗口 → ROS2”禁用，悬停给出安装方法；启动日志写一次 |

## 2. 实现

| 部分 | 文件 | 说明 |
| --- | --- | --- |
| 显示配置 | `engine/viz/`（新，不依赖 ROS2 与界面） | `.terviz` 读写：已知参数严格校验，不认识的参数、窗口与顶层字段警告并原样保留；预留 `overlays`、`extensions`；导出器接口、注册表、参数清单与校验；`.terviz`、`.rviz` 两个导出器 |
| 监视器 | `engine/ros2/{include/terra/ros2/monitor.hpp,src/monitor.cpp,src/runtime.*}` | 独立节点 `terra_monitor_<pid>`；每秒刷新图；通用订阅（按发布者的 QoS 选择）；运行时加载 introspection 与 typesupport 库，反序列化并展开；字段路径取值；频率与带宽（5 秒窗口）；图像换算（调用时进行）；TF 树。rclcpp 的初始化与关闭改为桥接与监视器共用 |
| 资源库 | `engine/library` | 资产新类型 `display`，扫描资源库目录下的 `displays/`，关联场景 |
| 设置 | `engine/settings` | `interface.sceneDisplays`：每个场景上次使用的显示配置 |
| 查看器 | `apps/viewer/viz_panel.*`、`main.cpp`、`library_panel.cpp` | 窗口、导出与另存为弹窗、按配置同步订阅、保存 / 恢复 / 导入（拖入 `.terviz`）、`--viz-self-test` |
| Headless | `apps/headless` | `--list-assets --kind display` |

**变异测试（8 个）：**
- 不认识的参数不保留；
- 导出参数不校验范围；
- `.rviz` 漏掉固定坐标系；
- 频率按条数计算；
- 数组下标不检查越界；
- 16UC1 不换算为米；
- `/tf_static` 不标为静态；
- 打开场景时不恢复显示配置。

**预期：**渲染关闭 100/100；渲染开启 137/137；含 ROS2 151/151；ASan 含 ROS2 14/14。

## 4. 基线结果

**第一次运行：**编译错误（ImGui 1.92.8 起 `AddPolyline` 的粗细与标志换了位置）与 `-Wshadow`。已修正。第二次运行时修改还没同步到基线机器，结果相同。

**第三次运行：**100/100、137/137、137/137；ASan 109/109 + 28/28；变异 8/8；含 ROS2 150/151，ASan 含 ROS2 13/14。
- `ros2.monitor` 全部通过：100.0 Hz、600 条，曲线与正弦的偏差为 0，PNG 解码、宇树 LowState 35 项；
- 失败的是 `graphics.viewer_ros2_panel_selftest`：面板发现了话题、TF 树有 7 个变换，但 IMU 消息、相机图像与 IMU 曲线都没有收到数据；
  保存、恢复、导出都通过。
- **原因判断：**`ros2.monitor` 中发布者在另一个进程，通用订阅正常；查看器中桥接与监视器同在一个进程、共用默认的 rclcpp 上下文
  （同一个 DDS 参与者），用类型化订阅的 TF 收到了，通用订阅却没有收到。
- **修改：**监视器改用自己的 rclcpp 上下文（独立的 DDS 参与者，与跨进程相同），也更符合“监视器独立于桥接”的设计；
  自检在数据到达前最多再等 9 秒，并打印每个话题的订阅状态、收到的条数、类型问题与 QoS，便于再次失败时定位。

## 5. 与设计稿的差别

- 仿真相机的画面弹出为图像窗口：本步没有做（曲线已做）。仿真相机的画面在开启桥接时可以经 ROS2 的图像窗口查看。
- 压缩图像沿用渲染模块已有的 `decodeImage`，没有新增解码函数（设计稿已改）。
- “类型库缺失”的情况：测试中无法构造（发布者与监视器在同一环境中），由代码路径给出提示，没有自动化测试。

**第四次运行：**含 ROS2 的 Release 中查看器自检停在阶段 2（等数据超时），仿真在 10.9 秒内只推进了 65 步；ASan 构建中只剩消息、图像、曲线三项失败（TF 已收到）。
- **真正的原因（更正第三次的判断）：**带 `--ros2` 启动时仿真已经在运行，自检第 3 帧的“播放 / 暂停”反而把它暂停了，
  桥接只发布了开始几步的消息，所以消息、图像与曲线都没有数据（第三次运行也是如此，只有 /tf_static 因为 transient local 收到）。
- **修改：**显示配置自检在开始与等待数据时确保仿真在运行。监视器使用独立 rclcpp 上下文的修改保留（符合“独立于桥接”的设计，
  ASan 构建中 TF 在独立上下文下正常收到）。

**第五次运行：全部通过。**
- 100/100、137/137、137/137；ASan 109/109 + 28/28；含 ROS2 151/151；ASan 含 ROS2 14/14；变异 8/8。
- 查看器 ROS2 面板自检：IMU 话题收到 1503 条（502.4 Hz），消息树展开 253 次；相机图像 90 帧（30.0 Hz），上传 89 次；
  ROS2 曲线 1503 个点；TF 15 个变换；保存 6 个窗口，重开场景后恢复 6 个；导出的 `.rviz` 含 Image 与 TF，列出 7 项未导出的部分。
- 小修：话题的 QoS 说明中显示了“keep last 0”——从图中查到的发布者 QoS 不含深度（DDS 发现不传递），改为不显示深度。只影响悬停提示的文字，没有重新验证。
