## 1. 用户能做什么

| 入口 | 行为 |
| --- | --- |
| 场景文件 | 写法：`{"type": "lidar3d", "name": "go2/mid360", "entity": "go2/base", "position": […], "preset": "livox_mid360", "imu": true}`。<br>可选项：<br>· 覆盖量程、点频、帧率；<br>· `noise`：关闭或改参数；<br>· `motionDistortion`（默认开）；<br>· `pattern`：自定义扫描图案；<br>· `hits`。<br>场景 `assets/scenes/robots/go2_mid360.terra-scene.json`：Go2 机身上方装一个 Mid-360 |
| 查看器 | 视口中叠加点云，按高度着色，类似 RViz，可关闭；传感器面板中有俯视与侧视图、点数与频率；资源库的场景卡片带“3D 激光雷达”标签 |
| Headless | `--sensors`：每帧一行 `lidar3d`，含帧序号、第一点时刻、射线数、点数、距离与高度范围、内容摘要 |
| `terra_capture` | 每个雷达写 `lidars3d/<名>/frames.jsonl` 与每帧 `.npy`（float32，形状 (点数, 5)：x、y、z、time、line） |
| ROS2 | `<名>/points` 发布 `sensor_msgs/PointCloud2`，字段与 `livox_ros_driver2` 相同：x、y、z、intensity、tag、line、timestamp（纳秒）。<br>消息头为第一点的测量时刻，可用 `topics` 映射成真机的 `/livox/lidar`。<br>内置 IMU 发布在 `<名>_imu/imu` |
| 实验记录 | 每帧记点数与摘要（点本身体积太大）；复现时重算并逐位比较 |

## 2. 模型

| 项 | 做法 | 依据 |
| --- | --- | --- |
| 扫描图案 | Livox 官方仿真插件的 `mid360.csv`：800,000 个方向，即 4 s × 200,000 点/秒。<br>第 f 帧取第 f × 20,000 起的 20,000 个方向，4 s 循环（非重复扫描） | MIT，锁定提交 `1cce1073`、sha256 `aa1fc08b…`；由 `scripts/assets/fetch_lidar_patterns.sh` 下载 |
| 参数 | 360° × (−7°～52°)、10 Hz、40 m（10% 反射率；可改 70 m）、盲区 0.1 m | Livox 规格页 |
| 距离噪声 | σ 在 0.2 m 处 3 cm 与 10 m 处 2 cm 之间按距离线性插值 | 规格页（≤ 3 cm @ 0.2 m，≤ 2 cm @ 10 m） |
| 方向噪声 | 方位与俯仰各 σ 0.15° | 规格页（< 0.15°） |
| 运动畸变 | 第 i 点在帧内的 i ÷ 点频 时刻测得，最后一点即当前时刻。每 1 ms 一组射线，按该时刻的安装位姿发出（由安装点的线速度与角速度回推）。点在各自时刻的安装坐标系中，与真机相同，供 FAST-LIO 等按每点时间去畸变。可关闭 | 真机的测量方式 |
| 下边缘随方位变化 | 官方图案的最低仰角不是处处 −7.2°：左右（±90°）−7.2°，前后（0°、180°）−4.9°，按方位平滑变化；上边缘同样在 48.3°～52.2° 之间变化。水平安装时地面盲区的内边界因此前后长、左右短（0.4 m 高时约 3.94 m 与 3.16 m）。Terra 照图案执行，测试“地面圆环”检查与图案的解析值一致、前后左右对称 | 由 `mid360.csv` 统计；规格页只给 −7°～52°，手册写“垂直最大 59°”。真机是否如此未核实（第 5.2 节） |
| 线号 | 图案序号对 4 取余 | Mid-360 为 4 线；Livox 图案中线号的对应方式未公开，这是假设 |
| 内置 IMU | 位置 (11.0, 23.29, −44.12) mm，200 Hz；陀螺 0.0045 °/s/√Hz，加速度计 100 µg/√Hz | Mid-360 用户手册 v1.2；TDK ICM-40609-D 数据手册 DS-000330 v1.2 |
| 不模拟 | 反射率与强度（intensity 固定为 100）、多回波、雨雾、其他物体在 0.1 s 内的运动 | 写进报告 |

**射线检测提速：**`PhysicsWorld::castRays` 改用 MuJoCo 的 `mj_multiRay`：同一起点的射线共用几何体的包围检测。打到不参与碰撞的几何体的射线，再逐条用 `mj_ray` 继续。2D 雷达同样受益，读数的含义不变。

## 3. 与开源实现的比较（用户 2026-11-26 提示参考）

参考的开源实现是 [MuJoCo-LiDAR](https://github.com/discoverse-dev/MuJoCo-LiDAR)（MIT）。它的 CPU 后端同样用 `mj_multiRay`，Mid-360 图案也来自 Livox 的同一份数据（`mid360.npy`）。

| 项 | MuJoCo-LiDAR（`scan_gen_livox` 的 mid360 设置） | Terra |
| --- | --- | --- |
| 每次的点数 | 24,000（与帧率无关） | 20,000（= 200,000 点/秒 ÷ 10 Hz，与规格一致） |
| 最大量程 | 200 m | 40 m（10% 反射率），可改 70 m；盲区 0.1 m |
| 图案的推进 | 每调用一次前进一段（与仿真时间无关） | 按仿真时间的帧序号，同一时刻总得到同一帧，可复现 |
| 噪声 | 没有看到 | 距离与方向，按规格页；带种子、可关闭 |
| 每点时间与运动畸变 | 没有看到 | 每点测量时刻、按时刻回推位姿 |
| 内置 IMU | 没有 | 按用户手册的位置与数据手册的噪声 |
| 记录与复现 | — | 逐位复现 |
| GPU 后端 | Taichi / JAX / Warp | 只有 CPU（`mj_multiRay`）；单帧耗时见第 4 节，需要时再评估 GPU |

### 5.2 第二次运行（2026-11-26）

**结果：**

| 项 | 结果 |
| --- | --- |
| 扫描图案 | 2/2（镜像修正生效） |
| 渲染关闭 / 渲染 Debug / 渲染 Release | 111 / 152 / 152，全部通过 |
| ASan | 120 + 32，全部通过 |
| 含 ROS2 | 167/168；ASan 含 ROS2 15/16：同一项 `ros2.lidar3d` |
| Mid-360 一帧 | 20,000 条射线、20,000 个点，3.82 ms；按帧推进、4 s 循环都通过 |
| 变异 | 6/6 |
| 可交互展示 | 退出码 0 |

**`ros2.lidar3d` 失败的原因：**检查“点在房间的墙面上”要求最远距离小于 3.7 m，这个上限是我算错的。网格中方位 30°、天顶角 60° 的射线正好打到墙角 (3, 1.73, 2)，距离 4.0 m。Headless 测试的上限是 4.0，只是靠 3.9999 侥幸通过。

**修正：**两处都改为“最远 3.9～4.01 m、最近 1.0～1.2 m”。

**用户观察：**真机或 RViz 中 Mid-360 点云的中间印象是圆形，Terra 的看起来像梭形。

**查证：**
- 统计官方图案后确认，最低仰角随方位变化（第 2 节）。这是图案本身的特点，不是 Terra 的坐标换算错误：Terra 由天顶角与方位角换算方向，仰角范围与规格一致。
- 平地上水平安装时，盲区内边界前后约 3.94 m、左右约 3.16 m，看上去前后长。
- 斜着看视口叠加时，地面上的环会被透视压扁，也会显得更扁。
- 真机是否也这样还没有核实。规格页只写 −7°～52°，网上没有找到相关描述；Livox 规格页提供的 FOV 三维模型可以对照。

**新增：**
- 夹具 `lidar3d_ground.*`：Mid-360 水平装在 0.4 m 高，只有地面。
- `simulation.lidar3d` 增加检查：40 帧中每 30° 扇区的盲区内半径与图案的解析值一致（0.2% 以内），且相对的扇区相同（不偏心）。
- 验证脚本的展示前先打开 20 秒俯视。

**待用户核对：**如果有真机的 rosbag，录一段水平放在平地上的数据，就能对照盲区形状。

**用户反馈：**
- 平放时从中心到外围的地面也呈梭形，数据对得上就可以。
- 用户观察过的是倒置的 Mid-360，问是否与此有关。

**分析：**有关。倒置时视场朝下（−52°～7°），地面由图案的上边缘决定。上边缘随方位的变化小（48.3°～52.2°），盲区只有 0.31～0.34 m，前后与左右只差 9%。八成以上的射线打到地面，中间是接近圆形的密集区。正装时地面由下边缘决定（−4.9°～−7.2°），掠射角小，同样的角度差使盲区差 25%。

### 5.4 运行后的补充（随下一次运行验证）

**倒置：**
- 夹具 `lidar3d_ground_inverted.terra-scene.json`：绕 X 轴转 180°。
- 测试“地面圆环（倒置）”：内半径与上边缘的解析值一致，0.30～0.35 m；八成以上的射线打到地面。
- 场景卡片“宇树 Go2 + Mid-360（倒置）”：倒挂在机身前上方。
- 展示时先开正装、倒置两个 20 秒的俯视窗口。

**外观模型：**
- 来源：`mathaimp/livox_gz_sim`（MIT，提交 `3f06f1ac`）的 `mid360.dae`。这是按用户手册尺寸自建的低面数模型（65 × 65 × 60 mm，原点在底面中心），不是由 Livox 的 CAD 转换来的，许可清楚。
- 获取：`scripts/assets/fetch_sensor_models.sh` 下载，按 sha256 校验；再由 `scripts/assets/dae_to_glb.py`（只用 Python 标准库，输出确定）转为 glb，放在 `assets/sensors/models/`，不提交。
- 预设：`model` 给出 glb 与位姿（底面在点云原点下方 47 mm，用户手册）。场景解析时自动加一个跟随安装实体的 glTF 绑定（`sensorModel`），不影响实体的 MJCF 几何体是否隐藏；场景写 `"model": false` 关闭。没有模型文件时只给警告，读数不受影响。
- 测试：外观模型相对支架的位置（正装 z = −0.047，倒置 z = +0.047）。新增变异“外观模型不按预设偏移”，共 7 个。
- 修正：`m2_05` 的一个锚点受改动影响，含义不变；锚点 322/322 唯一。
