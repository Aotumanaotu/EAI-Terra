## 1. 目标与验收

| 目标 | 验收 |
| --- | --- |
| 看见 ROS2 网络上的一切：节点、话题（类型、发布 / 订阅数、QoS、实测频率与带宽） | 仿真自己发布的话题、外部节点（如 `ros2 topic pub`）发布的话题都能列出，频率与实际一致（误差有阈值） |
| 任意消息查看：不需要事先编译该类型的代码 | 标准消息（`Imu`、`LaserScan`、`JointState`、`Odometry`、`TFMessage`）与第三方消息（宇树 `LowState`，35 个电机的数组）逐字段与发送的值一致 |
| 曲线：任选数值字段画随时间的曲线，可多条 | 已知正弦的话题画出的曲线与发送值一致 |
| 图像：`Image`（rgb8、bgr8、mono8、16UC1、32FC1）与 `CompressedImage`（JPEG、PNG） | 已知图案的图像像素一致；深度图伪彩色与传感器面板相同 |
| TF 树 | 由 `/tf`、`/tf_static` 建树；父子关系、最新变换与时间正确 |
| 显示配置：以场景为核心，存入资源库，**打开场景时自动恢复** | 保存后关闭、重开场景：打开的面板、话题、字段、曲线与图像窗口恢复 |
| 导出：弹窗选择 `.terviz`、`.rviz` 或两者 | `.terviz` 可以再导入；`.rviz` 能被 RViz2 打开，并列出没有导出的部分 |
| 没有 ROS2 时 | 面板不出现；菜单中写明“未检测到 ROS2 Humble”，并给出安装说明；其他功能不受影响 |

## 2. 结构

```
        查看器（只在 TERRA_WITH_ROS2 时编译 ROS2 部分）
 ┌───────────────────────────────────────────────────────┐
 │ ROS2 面板 · 消息窗口 · 曲线窗口 · 图像窗口 · TF 树      │
 │      ↑ 每帧取快照（加锁复制，不在界面线程收消息）       │
 ├───────────────────────────────────────────────────────┤
 │ terra::ros2::Monitor（新，engine/ros2）                │
 │   自己的节点 terra_monitor + 执行器线程                  │
 │   · 1 Hz 刷新节点与话题图（名字、类型、发布/订阅、QoS）   │
 │   · 只订阅界面打开的话题（通用订阅，收序列化消息）        │
 │   · 按 introspection 类型信息在运行时展开               │
 └───────────────────────────────────────────────────────┘
        与仿真的桥接（Bridge，M4-06）相互独立
```

- **监视器与桥接分开**（问题 1）：
  - 监视器不需要打开场景，也不需要开启桥接，连真机时同样可用（Sim-to-Real 时并排观察）；
  - 公共头 `terra/ros2/monitor.hpp` 不含 ROS 类型，与桥接的约束相同；
  - 消息展开后是 Terra 自己的值树（名字、类型、数值或字符串、子节点）。
- **任意类型：**
  - 用 rclcpp 的通用订阅收序列化消息；
  - 按话题类型动态加载 `rosidl_typesupport_introspection_cpp`，再反序列化并展开；
  - 宇树等第三方消息只要在环境中（已 source）就能看；找不到类型库时，该话题标“无法解析的类型”。
- **只订阅打开的话题：**话题表只读图信息，不订阅。频率与带宽在打开该话题后统计（与 `ros2 topic hz / bw` 相同）。表中的“订阅后统计”列为空时显示“—”。
- **代价控制：**
  - 消息窗口每帧只展开最新一条；
  - 曲线只取所选字段（每条消息都取，否则曲线会丢点），每个话题最多保留 60 秒；
  - 图像只保留最新一帧，在界面线程上传纹理。

## 3. 界面

一键优先（M4-08c 的修正）：常用的事情在话题行上点一下就能完成。

```
┌ ROS2 ─────────────────────────────────────────────────────────┐
│ [搜索话题…]          节点 12  话题 31     显示配置：[默认 ▾] [保存] [导出…] │
│ 话题                     类型                 发布 订阅  Hz    带宽   │
│ ▸ /scan                  sensor_msgs/LaserScan  1   0   8.0   34 KB/s [消息][曲线]       │
│ ▸ /oakd/rgb/preview/…    sensor_msgs/Image      1   0  15.0  2.7 MB/s [消息][图像]       │
│ ▸ /imu                   sensor_msgs/Imu        1   0 100.0   32 KB/s [消息][曲线]       │
│ ▸ /tf                    tf2_msgs/TFMessage     1   0  50.0           [TF 树]           │
└───────────────────────────────────────────────────────────────┘
```

| 部分 | 做法 |
| --- | --- |
| **话题表** | 可排序、可拖动列宽；搜索框按名字或类型筛选；节点在另一个分页（节点名、发布与订阅的话题） |
| **行尾的按钮**（按类型给出） | 一般话题：消息、曲线；图像：图像；TF：TF 树 |
| **消息窗口**（每个话题一个，可停靠或浮动） | 字段树，按需展开；长数组分页，每页 100 项；右键数值字段或点字段旁的曲线图标即可“加入曲线” |
| **曲线窗口** | 多条曲线：可以来自不同话题，也可以来自仿真自己的传感器；时间轴默认用接收时间，可切换为消息头时间（问题 2）；暂停与缩放 |
| **图像窗口** | 编码按第 1 节；深度图伪彩色的范围可调；显示分辨率、帧率与延迟 |
| **TF 树** | 树形列出父子关系，显示平移、旋转（四元数与欧拉角）与“多久没更新”（超过 1 秒标黄）；静态变换另作标记 |
| **没有 ROS2** | “窗口 → ROS2”显示为禁用，悬停写明“未检测到 ROS2 Humble”与安装方法（`sudo apt install ros-humble-desktop`，并在启动前 `source /opt/ros/humble/setup.bash`）；日志里写一次 |

**与仿真的传感器统一**（11.7 节问题 2）：
- 曲线控件与图像控件改为传感器面板与 ROS2 面板共用；
- 传感器面板中的 IMU 曲线、相机画面也能“加入曲线 / 弹出为图像窗口”，并随显示配置保存（来源标为“仿真”）。

## 4. 显示配置

**内容**（`.terviz`，JSON）：

```json
{
  "format": "terra.viz",
  "version": 1,
  "name": "导航调试",
  "scene": "../../../scenes/robots/turtlebot4.terra-scene.json",
  "windows": [
    {"type": "topics"},
    {"type": "message", "topic": "/odom", "params": {"pageSize": 100}},
    {"type": "plot", "title": "角速度",
     "params": {"seconds": 10, "timeBase": "receive", "yRange": "auto",
                "series": [{"source": "ros2", "topic": "/imu", "field": "angular_velocity.z"},
                           {"source": "sim", "sensor": "turtlebot4/imu", "field": "gyro.z"}]},
     "placement": {"position": [0.62, 0.08], "size": [0.3, 0.25], "docked": false}},
    {"type": "image", "topic": "/oakd/stereo/image_raw", "params": {"depthRange": [0.2, 5.0], "colormap": "turbo", "fit": "fit"}},
    {"type": "tf"}
  ],
  "overlays": [],
  "extensions": {}
}
```

- **存放：**资源库目录下的 `displays/`，登记为资产新类型“显示配置”，关联到场景。
  - 一个场景可以有多份，用户可以命名；
  - 资源库面板中场景卡片上的标签显示份数；也可以在卡片右键菜单中直接选择某一份打开。
- **自动恢复**（问题 3）：
  - 打开场景时恢复它上次使用的那一份；
  - 没有时不打开任何 ROS2 窗口（与现在相同）；
  - 改动后标“未保存”，点“保存”写回（不自动保存，避免试验时的临时窗口覆盖配置）。
- **窗口位置**（问题 4）：按窗口在主窗口中的相对位置与大小保存（换分辨率也合适）。停靠状态只记录“停靠 / 浮动”；具体停在哪里仍跟随全局布局。
- **导入：**把 `.terviz` 拖进窗口，或在 ROS2 面板中选“导入…”。场景路径不存在时，关联到当前场景。

**导出**（M4-08 评审答复 8）：弹窗中选择导出的类型。

```
┌ 导出显示配置 ─────────────────────────────┐
│ 名称：导航调试                              │
│ [✓] Terra 显示配置（.terviz）                │
│ [✓] RViz2 配置（.rviz）                     │
│     固定坐标系：[odom ▾]（取 TF 树的根）      │
│     不能导出到 RViz 的部分（2 项）：          │
│       · 曲线“角速度”（RViz 没有曲线）         │
│       · /odom 的消息窗口（RViz 没有消息查看）  │
│ 保存到：[~/…/displays/]  [浏览…]             │
│                       [导出]  [取消]         │
└───────────────────────────────────────────┘
```

**`.rviz` 的对应关系**（问题 6）：

| Terra 窗口 | RViz2 显示 | 说明 |
| --- | --- | --- |
| TF 树 | `rviz_default_plugins/TF` | — |
| 图像窗口（`Image`） | `rviz_default_plugins/Image` | `CompressedImage` 写为 Image，并设 `Transport Hint: compressed` |
| `LaserScan` 话题的消息或曲线 | `rviz_default_plugins/LaserScan` | — |
| `PointCloud2`、`Odometry`、`PoseStamped`、`Path`、`Marker`、`MarkerArray` | 对应的默认插件 | 用户打开过该话题时导出 |
| 曲线、消息窗口、仿真来源的窗口 | 无 | 列在弹窗中，并写在 `.rviz` 文件开头的注释里 |

另外总是加上 Grid、视角（Orbit）与固定坐标系。导出的文件按 M4-08b 中手写的 `terra_turtlebot4.rviz` 的结构生成。

### 4.1 扩展的余地（用户评审时的要求）

**导出格式可以增加，不改界面：**
- 导出器是一个接口：
  - 标识、显示名、文件后缀；
  - 参数清单：每个参数有键、显示名、类型（文本 / 数值 / 开关 / 选项）、默认值、可选值；
  - 转换函数：输入显示配置与参数值，输出文本与“未导出的部分”清单。
- 导出器注册在一张表中。导出弹窗按表列出所有格式，各格式的参数按清单自动生成控件。
- 以后增加 Foxglove 布局、PlotJuggler 布局等，只需新写一个导出器。
- 本步注册两个导出器：
  - `.terviz`：没有参数；
  - `.rviz`：参数为固定坐标系（从 TF 树中选，也可以手填）、网格开关、视距、帧率。

**显示配置的参数可以增加，旧程序不丢内容：**
- 每个窗口为 `type` 加 `params`（对象）。已知的参数严格校验，类型错误时报错；
- 不认识的参数或窗口类型（来自更新的版本）给出警告，并**原样保留**，保存时写回，不丢失；
- 顶层预留 `overlays`（视口叠加，B 层）与 `extensions`（第三方扩展）两个字段，本步只读写、不使用；
- `version` 只在不兼容时增加，新增参数不改版本号。

**本步各窗口的参数：**
- 曲线：时长、时间轴、纵轴范围（自动或固定）；每条曲线另有标签、颜色、比例与偏移；
- 图像：深度范围、色表（turbo / 灰度）、缩放方式；
- 消息：数组每页的条数；
- TF 树：只看某个坐标系之下的子树；
- 话题表：筛选文字。

导入也按同样的方式注册（本步只有 `.terviz`），以后可以加入 `.rviz` 的导入。

## 5. 实现

| 部分 | 位置 | 说明 |
| --- | --- | --- |
| 监视器 | `engine/ros2/{include/terra/ros2/monitor.hpp,src/monitor.cpp,src/introspection.cpp}` | 节点、执行器线程、图信息、通用订阅、运行时展开、频率与带宽统计、字段取值（路径如 `position[3]`） |
| 显示配置 | `engine/viz/`（新，**不依赖 ROS2**） | `.terviz` 的读写与校验（保留不认识的内容）；导出器接口与注册表；`.terviz`、`.rviz` 两个导出器。没有 ROS2 的构建也能测试 |
| 资源库 | `engine/library` | 资产新类型“显示配置”（`kind = display`）；扫描 `displays/` |
| 图像解码 | `engine/render`（stb 只允许在这里） | 沿用已有的 `decodeImage`（glTF 贴图用的 JPEG / PNG 解码），由查看器交给监视器 |
| 共用控件 | `apps/viewer/plot_view.*`、`image_view.*` | 传感器面板改用它们 |
| 查看器 | `apps/viewer/ros2_panel.*` | 面板、各窗口、显示配置的保存 / 恢复、导出弹窗；`--ros2-panel-self-test` |

## 9. 需要评审的问题

| # | 问题 | 建议 | 其他选项 |
| --- | --- | --- | --- |
| 1 | 监视器与桥接 | 分开：监视器是独立的节点，不打开场景也能看 ROS2 网络（含真机） | 复用桥接的节点（只能在开启桥接时使用） |
| 2 | 曲线的时间轴 | 默认用接收时间（任何消息都有，仿真与真机可以并排）；可切换为消息头时间（`header.stamp`，仿真时为仿真时间） | 只用消息头时间（没有 header 的消息画不了） |
| 3 | 显示配置的恢复与保存 | 打开场景时自动恢复上次使用的那一份；改动后手动保存 | 自动保存（试验时打开的临时窗口会覆盖配置）；或完全手动加载 |
| 4 | 窗口的位置 | 按相对主窗口的位置与大小保存，只记录停靠或浮动；具体停靠位置跟随全局布局 | 每份显示配置各存一份完整的停靠布局（切换配置时整个界面会跳动） |
| 5 | `CompressedImage` 的解码 | 用已有的 stb_image（在渲染模块中新增解码函数）；只支持 JPEG 与 PNG | 依赖 OpenCV 或 image_transport（体积大，增加 ROS 依赖） |
| 6 | `.rviz` 导出的范围 | TF、Image、LaserScan、PointCloud2、Odometry、Pose、Path、Marker（RViz2 默认插件中有的）；其余列出 | 只导出 TF 与 Image |
| 7 | 仿真传感器进入显示配置 | 是：曲线与图像窗口可以来自仿真（来源标“仿真”），与 ROS2 来源并排 | 显示配置只管 ROS2 窗口 |
| 8 | 显示配置的存放 | 资源库的 `displays/`，资产新类型，关联场景；场景卡片显示份数，右键可直接打开 | 写进场景文件（场景是内置只读资产时无法保存） |
