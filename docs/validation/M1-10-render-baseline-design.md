# M1-10 渲染测试、参考图与帧耗时基线（设计稿）

> 状态：设计**评审通过**（用户 2026-11-22，第 6 节 5 项全部同意；“不着急，按顺序来，尽量做得完美”）；**已实现并通过基线验证、已验收（M1-11，2026-11-23 用户评审通过）**（第 7–9 节；4 组带资产的帧耗时数值已在 M1-15 验证中补录）。关联 F-M1-03、NFR-06、D-022（像素基准以 llvmpipe 为准）、D-027。
> M1-10 完成后进入 M1-11 阶段验收（沿用 M0-09 做法）。

## 1. 现状

开发计划 M1-10 的第一项“离屏渲染并回读像素的自动测试（单独标签，不阻塞无图形测试）”已在 M1-06 起逐步具备：`graphics` 标签的 7 项测试在 Xvfb + llvmpipe 中无人值守运行，像素与 C++ 参考实现逐点比较。尚缺的是：

1. **整幅画面的参考图**：现在只检查少数几个像素；整体画面的回归（例如阴影边缘、网格、贴图细节、色调映射变化）没有被覆盖。
2. **帧耗时基线**：只有展示时的平均帧率（受垂直同步限制，恒为 60 FPS），没有不受垂直同步影响的 CPU/GPU 耗时与各渲染阶段的分解。

## 2. 参考图测试

| 项目 | 设计 |
| --- | --- |
| 场景 | ① **程序场景**（立方体、材质球、圆柱、胶囊、半球光、太阳阴影、网格），不依赖下载素材，总是运行；② **摄影棚 + 三个资产**（IBL、贴图材质）；③ **室外 + 三个资产**（贴图中的太阳、阴影、背景）。②③ 在素材不存在时报告“跳过”（CTest 的 SKIP 返回码），不算失败 |
| 分辨率与设置 | 640 × 360，4× MSAA，AgX，固定相机与光照；只在 llvmpipe 上比较（D-022） |
| 存储 | 参考图为 PNG，提交在 `tests/render/reference/`（每张约 0.3 MB 以内）；写 PNG 需要 **stb_image_write**（与已锁定的 stb_image 同一仓库、同一提交，公有领域/MIT） |
| 比较规则 | 逐像素：每个通道差 ≤ 3/255 视为相同；不同像素占比 ≤ 0.1%，且最大差 ≤ 16/255 时通过。失败时在构建目录写出实际图、差异图（放大 8 倍）与统计 |
| 更新参考图 | 只能在基线机器上显式运行 `scripts/verify/update_references.sh`（写入新参考图并打印差异统计），再由人确认后提交；验证脚本不会自动更新 |

## 3. 帧耗时基线

| 项目 | 设计 |
| --- | --- |
| 程序 | 新增 `terra_render_bench`（与 M0-09 的 `terra_bench` 同一做法）：创建隐藏窗口，离屏渲染查看器的演示场景，**不经过垂直同步** |
| 测量 | 预热 60 帧后测 600 帧；CPU 每帧耗时与 **GPU 每帧耗时（OpenGL 计时查询，4.5 核心功能）**；GPU 再按阶段分解：阴影、不透明物体、背景、网格、解析、色调映射 |
| 配置 | 1920 × 1080 与 3840 × 2160 两种分辨率；室外 IBL + 资产 + 阴影 + 4× MSAA（默认画质），另测关闭 MSAA、关闭阴影各一次以便比较 |
| 输出 | 每帧 JSON Lines 与汇总（平均、中位数、p95、p99、最大），写到构建目录；报告记录 GPU、驱动、分辨率、设置 |
| 判定 | 基线机器 RTX 5060 上记录数值作为基线；**不设硬性门槛**（llvmpipe 只做“能跑完”的冒烟测试）。若 4K 默认画质 GPU 中位数超过 16.7 ms，在报告中列为风险 |
| 查看器 | 统计面板增加 GPU 各阶段耗时（同一计时查询，按秒平滑） |

## 4. 画质路线的取舍（M1-09 设计第 7 节，需要你决定）

M1-09 之后，质感上最明显的不足是“物体接触处不变暗”。可选：

| 方案 | 内容 | 工作量 | 建议 |
| --- | --- | --- | --- |
| A | **使用 Poly Haven 资产自带的 AO**：这些资产的 ARM 合并贴图 R 通道就是 AO，只是材质没有声明；增加一个“按 ARM 约定读取遮蔽”的选项（检测到金属度-粗糙度贴图为 `*_arm*` 时启用，可关闭） | 小 | **建议在 M1-10 做** |
| B | **屏幕空间环境遮蔽（GTAO）**：所有物体接触处、缝隙自然变暗，不依赖资产 | 中（新的渲染阶段、深度/法线缓冲、降噪） | 建议放到 M3（机器人展示与画质评估）再做，让 M1 尽快收尾、进入 M2 仿真同步 |
| C | 级联阴影、泛光、屏幕空间反射 | 中到大 | M3 |

## 7. 实现

| 位置 | 内容 |
| --- | --- |
| stb_image_write 1.18 | 与 stb_image 同一提交（`9f755b60…`），sha256 `a8e7f77f…10d9e7ca` 记入 `third_party/stb/stb.lock`，`check_stb.sh` 复核 3 个文件（开发机已与官方比对一致）；实现与 stb_image 同在 `stb_image_impl.cpp` |
| `terra/render/image.hpp` | `savePng`、`fromBottomUp`（GL 回读行序 → 图像行序）、`compareImages`（第 2 节规则，忽略透明度）、`differenceImage`（灰度 × 8，超差像素为红） |
| `SceneRenderer` | GPU 时间戳计时：每帧 7 个时间戳、3 帧轮换不阻塞；`lastTimings`（查看器统计面板）与 `waitForTimings`（基准程序逐帧等待）；阶段：阴影、物体、背景、网格、解析、色调映射 |
| `terra_viewer_scene`（新库） | 从 `main.cpp` 移出演示场景、环境贴图库（含太阳提取）、设置→渲染参数换算与 `frameLighting`；查看器、参考图测试、基准程序共用，画面一致；日志以 `SceneMessage` 返回，由查看器翻译 |
| `terra_render_bench`（新程序） | 隐藏窗口离屏渲染，`--width/--height/--frames/--warmup/--scene/--msaa/--no-shadows/--output`；每帧 JSON Lines（整帧、提交、GPU 总计与各阶段），汇总平均 / p50 / p95 / p99 / 最大 |
| ARM 遮蔽约定（方案 A） | `loadGltf` 的 `LoadOptions::armOcclusion`（默认开）：材质无遮蔽贴图且金属度-粗糙度贴图文件名含 `_arm` 时，用同一贴图的 R 通道作为遮蔽并给出信息级诊断；`GpuAsset::items(…, armOcclusion)` 与设置 `render.assetArmOcclusion` 可实时开关 |
| 查看器 | 统计面板显示 GPU 总耗时与各阶段（平滑）；“渲染”分组新增 ARM 遮蔽开关 |
| 参考图流程 | `scripts/verify/update_references.sh`：只在基线机器上、只用 llvmpipe 生成，先与现有参考图比较再写入，打印 sha256；参考图提交在 `tests/render/reference/` |

## 8. 测试

| 测试 | 内容 |
| --- | --- |
| `render.image_compare`（新增，CPU） | 相同图通过；容差内不计；10 个像素差 10（0.1%）通过、11 个失败；单像素差 17 失败；透明度不参与；尺寸不同；差异图灰度与红色；行序转换；PNG 往返逐字节相同；写入失败的诊断 |
| `graphics.render_reference.{procedural,studio,outdoor}`（新增） | 640 × 360、默认画质；同一场景渲染两次逐字节相同；与参考图比较；失败时写实际图与差异图；带资产的场景在素材缺失时跳过（返回码 77） |
| `graphics.render_bench_smoke`（新增） | 160 × 90、10 帧，输出格式正确 |
| `graphics.render_pbr`（扩充） | 计时：开启后第一帧等待即得有效且非负的分阶段耗时 |
| `asset.gltf`（扩充） | ARM 文件名规则；推断出遮蔽贴图与信息级诊断；关闭推断；真实资产均推断出遮蔽 |
| `settings.store`（扩充） | `assetArmOcclusion` 默认值与往返 |

测试总数：渲染关闭 38；渲染开启 51 → **56**。

**变异测试（5 项，`scripts/verify/m1_10.sh`）**：比较规则永远通过、差异图不标出超差像素、回读行序没有翻转（→ `render.image_compare`）；计时没有等待本帧结果（→ `graphics.render_pbr`）；ARM 约定识别失效（→ `asset.gltf`）。

**帧耗时基线（第 6 步，RTX 5060，各 600 帧）**：1080p 默认画质；4K 默认画质；4K 无 MSAA；4K 无阴影；4K 程序场景。结果写入 `build/verify-m1-10/logs/bench_*.jsonl`，汇总记入本报告。
