## 3. 关键验证结论

- **M0 统一验收：**三种配置均 35/35，11 项变异全部被发现；35 项测试每项至多重复 5 次均通过。
- **M0 性能：**立方体 step/snapshot/jsonl 平均约 5.448/5.846/11.722 µs/步；铰链约 1.863/1.841/7.052 µs/步。只记录，不设通过门槛。
- **OpenGL 环境：**桌面默认和 NVIDIA PRIME 均为 RTX 5060 OpenGL 4.6；Xvfb + llvmpipe 为 OpenGL 4.5，因此最低版本定为 4.5 core。
- **渲染依赖：**三个源码包 SHA-256 与锁定值一致；glad 重新生成与仓库逐字节一致；GLFW 的 X11 与 Wayland 后端均成功构建。
- **M0 回归隔离：**渲染关闭仍 35/35；渲染开启 Debug 和 Release + `-Werror` 均 36/36。
- **真实 GPU：**RTX 5060 成功创建请求中的 OpenGL 4.5 core 上下文并完成像素回读。不同驱动的 0.5 颜色值回读存在 1 个灰度级舍入差异，自动像素基准固定使用 llvmpipe。
- **M1-03/04 全量验证：**渲染关闭 **37/37**；渲染开启 Debug、Release + `-Werror` 均 **41/41**；ASan/UBSan 非图形 38 项和图形 3 项全部通过；变异 **8/8 被发现**。
- **平台行为：**llvmpipe 上请求 OpenGL 4.6 确定性返回 `ContextUnavailable`，无显示返回 `NoDisplay`；窗口可晚于平台对象销毁，全部销毁后可重新创建平台。
- **输入行为：**覆盖快速点按、组合键、修饰键、轴向/径向死区、断开与失焦释放、动作表优先级和三种来源仲裁；GLFW 翻译表覆盖 **105/105** 个物理键位。
- **M1-06：**渲染关闭 37/37，渲染开启 Debug/Release **42/42**，ASan 全部通过、变异 **5/5**；验证深度遮挡、着色器行号、调试输出和 1000 个缓冲的 RAII 释放。RTX 5060 可见展示 4 秒 242 帧，垂直同步下约 60 FPS。
- **M1-07：**渲染关闭 37/37，渲染开启 Debug/Release **43/43**，ASan 全部通过、变异 **5/5**；相机数学与所有默认操作均有自动测试。用户桌面操作 43.4 秒后确认组合式控制“可以，没问题”，同时完成真实键鼠人工检查。
- **M1-12：**渲染关闭 **37/37**，渲染开启 Debug/Release **44/44**，ASan/UBSan 非图形 39 项和图形 5 项全部通过，变异 **3/3 被发现**。真实 DP-2 3840×2160@60Hz、27 种模式、内容缩放 1.25 的检查及 F11 试用通过。一个 Xvfb 等价变异已移出自动列表，改由真实显示器检查覆盖。
- **M1-13：**渲染关闭 **37/37**，渲染开启 Debug/Release **47/47**，ASan/UBSan 非图形 41 项和图形 6 项全部通过，变异 **5/5 被发现**。Xvfb 与 RTX 5060 自检均无 GL 错误，字体未回退，视口与窗口像素、菜单主题色正确；两种语言 1569 个界面字符在两个字体中均有字形。桌面展示 75.9 秒、约 60 FPS。

详细证据见 [M0-09](../validation/M0-09-acceptance.md)、[M1-01](../validation/M1-01-graphics-env.md)、[M1-02](../validation/M1-02-render-deps.md)、[M1-03/04](../validation/M1-03-04-platform-input-design.md)、[M1-06](../validation/M1-06-render-core.md)、[M1-07](../validation/M1-07-camera.md)、[M1-12](../validation/M1-12-display-modes.md)、[M1-13](../validation/M1-13-ui-shell-design.md)及[开发记录](DEVELOPMENT_LOG.md)。本次提交归档前执行静态检查，不新增编译或图形测试结果。

## 5. 保留风险与边界

- 平台窗口、输入、渲染核心、相机、显示模式和界面外壳已经实现，但材质、资产、真实场景面板和设置持久化尚未完成；当前测试通过不等于 M1 阶段完成。
- 自动图像测试依赖 Mesa/Xvfb 环境；跨 GPU 像素舍入不同，不能直接做无容差跨驱动比较。
- M0 容差仅适用于 MuJoCo 4.0.1、Euler 和当前夹具；升级或换积分器需重新评审。
- MuJoCo 致命错误可能终止宿主进程；球关节、flex 和复杂执行器覆盖在 M3 继续处理。
- 当前物理为单线程完整快照复制；物理与渲染并行发布在 M2 设计。
