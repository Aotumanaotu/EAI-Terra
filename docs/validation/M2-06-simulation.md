## 1. 交付：新模块 `terra_simulation`

该模块总是构建，没有图形依赖，只通过 `PhysicsWorld` 接口驱动世界。

| 组件 | 说明 |
| --- | --- |
| `FixedStepClock` | 每帧把墙钟增量 × 速度倍率累加，折算为整数个固定步。单帧最多推进 0.1 秒仿真时间（至少 1 步），超出部分丢弃，并记录过载次数与丢弃的时间。**物理步永远不跳过。**支持暂停（清空余量）、单步（暂停中也有效）、速度倍率。负数、NaN、无穷大的墙钟增量按 0 处理 |
| `interpolate` / `interpolatePoses` | 位置线性插值；姿态取最短弧后做归一化线性插值（nlerp）。两份快照属于不同世界实例、不同运行代次或实体数不同时**不插值**，直接用较新的一份 |
| `SimulationRunner` | 每帧 `update(墙钟增量)`，每一步依次：交出在该步生效的命令 → `step` → 记录快照（保留最近两份）→ 通知观察者。`displayPoses()` 按时钟余量在两份快照之间插值，画面比物理晚约一步；暂停时显示最新快照。`reset()` 形成屏障：清空命令队列、时钟余量与快照历史。步进出错后不再推进，直到 reset |

**命令按步序号生效：**`schedule(k, 命令)` 表示世界处于第 k 步时、推进到 k+1 之前交给 `setControl`。物理轨迹因此只取决于命令与步数，与帧率和帧间隔抖动无关。
- 安排在已经过去的步上的命令，在下一步之前生效，并计为“迟到”。
- 被 `setControl` 拒绝的命令（例如越界）在本帧结果中报告，仿真继续。
- 交互控制（例如键盘推动小车）用 `scheduleNext`，在下一步之前生效。这类控制本身与操作时刻有关，不在“逐位相同”的保证范围内。

**以后迁移到线程（D-106）：**快照以 `shared_ptr<const PhysicsSnapshot>` 发布，读者只持有不可变快照。把 `update` 的推进循环移到物理线程时，只需对“最近两份快照”的交换加锁，命令队列改为线程安全队列，公共接口不变。

## 2. 测试

| 测试 | 内容 |
| --- | --- |
| `simulation.logic`（新增，纯逻辑） | 30 / 60 / 144 / 240 / 1000 Hz 下 1 秒累计 500 步；整步不因舍入少算一步；卡顿 1 秒时只推进 50 步、过载 1 次、丢弃 0.9 秒，之后不补回；上限小于一步时至少 1 步；暂停、暂停中单步、继续、运行中单步；速度倍率与非法速度；异常墙钟增量；reset；位置插值、45° 中点、归一化、q 与 −q 走同一条最短弧、两端与截断；跨代次、跨世界、实体数不同时不插值 |
| `simulation.runner`（新增，使用 MuJoCo） | **帧率无关性**：两辆小车场景（每 100 步改变两车推力，共 1500 步）与下落立方体（接触，2000 步）分别在 30 / 60 / 144 / 240 Hz 与带抖动的帧间隔（4–40 ms，含一次 150 ms 卡顿，会触发追赶上限）下运行，**逐步比较全部实体位姿，要求逐位相同**。另覆盖：显示位姿位于两份快照之间；暂停时物理时间不增长、显示最新快照；暂停中单步；迟到命令；被拒绝的命令；reset 屏障（队列清空、历史只剩新代次、显示回到初始位置）；步进故障后不再推进，reset 后恢复 |

测试总数：渲染关闭 44 → **46**，渲染开启 62 → **64**。

变异测试 8 项（`scripts/verify/m2_06.sh`）：命令在帧开始时一次生效（帧率相关）、暂停时仍推进、超出追赶上限仍全部推进、reset 不清空命令队列、跨运行代次仍插值、四元数不取最短弧、暂停中的单步被忽略、暂停时显示插值而非最新快照。
