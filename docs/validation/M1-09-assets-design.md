# M1-09 资产加载（glTF）与材质真实感（设计稿）

> 状态：设计**评审通过**（用户 2026-11-22，第 9 节 5 项全部同意）；**已实现并通过基线验证、已验收（M1-11，2026-11-23 用户评审通过）**（第 10–13 节）。关联 F-M1-02、D-013（资产格式）、D-019（源码锁定）、D-027（自研 PBR）、开发计划 8.3（glTF 加载库待定）。

## 1. 为什么现在的材质“看起来不真实”

用户看完 M1-08b 后反馈：整体不错，但金属和其他材质的质感不真实。这是预期之内的阶段性结果。光照模型本身已经验证正确（像素与参考实现一致），不真实主要来自下面几点：

| 原因 | 现状 | 解决于 |
| --- | --- | --- |
| **没有纹理细节** | 每个物体只有一组常数参数（颜色、金属度、粗糙度）；真实表面的颜色、粗糙度有斑驳、划痕、磨损，法线有细小起伏。这是“像塑料 / 像 CG”的最主要原因 | **M1-09**：读取 glTF 的基础色、金属度-粗糙度、法线、环境遮蔽、自发光贴图 |
| **物体之间没有遮蔽** | 球与地面接触处、立方体底部没有变暗（环境光从各个方向都照得到），物体像“浮”在地上 | M1-09 先支持资产自带的 AO 贴图；屏幕空间环境遮蔽（SSAO/GTAO）列入画质路线 |
| **太阳与环境贴图不一致** | 室外 HDRI 里本身有太阳，我们另加的方向光方向与它不同：会出现两套高光、阴影方向与天空不符 | M1-09：从 HDRI 自动找出太阳方向与亮度，对齐方向光（可关闭） |
| **测试几何体太完美** | 完美的球、立方体，没有倒角；真实物体边缘总有细小倒角反光 | M1-09：用真实扫描或建模的资产 |
| **缺少后期** | 无泛光（亮处的光晕）、无景深 | 画质路线（低优先级） |

结论：M1-09 加载带完整 PBR 贴图的真实资产后，质感会有明显提升；其余几项见第 7 节画质路线。

## 2. 目标

开发计划 M1-09：选定 glTF 加载库；加载测试资产；处理单位、轴向（glTF 为 Y 向上）与缺失资源诊断；渲染公共接口不接收 MuJoCo 类型。本设计在此基础上加入**纹理材质**与**太阳对齐**，直接回应真实感问题。

## 3. 加载库（开发计划 8.3 待定项）

| 方案 | 说明 | 建议 |
| --- | --- | --- |
| **cgltf 1.15**（2025-02） | 单头文件 C，MIT；只做解析（JSON + 缓冲区 + 访问器），不读图像；零依赖；被 Filament、raylib、sokol 等广泛使用 | **建议采用** |
| tinygltf 3.1（2026-11） | C++，MIT；自带 JSON 与图像读取（依赖 stb_image、json.hpp）；体积大，API 偏重 | 不采用 |

图像解码沿用已锁定的 stb_image，新增 PNG 与 JPEG 解码（Poly Haven 的 glTF 贴图为 JPEG）。cgltf 与 stb_image 一样直接提交头文件并锁定 sha256。

## 4. 范围

| 项目 | M1-09 支持 | 暂不支持（报告诊断） |
| --- | --- | --- |
| 文件 | `.gltf`（外部 `.bin`、外部图像）与 `.glb` | Draco / meshopt 压缩、KTX2 贴图 |
| 场景 | 节点层级与变换（TRS / 矩阵）、多网格多图元 | 动画、蒙皮、变形目标、相机、灯光扩展 |
| 几何 | 三角形图元；位置、法线、UV0、切线（缺失时用 MikkTSpace 等价算法生成）、索引（8/16/32 位） | 线、点、三角带 |
| 材质 | `pbrMetallicRoughness`（基础色、金属度-粗糙度贴图与因子）、法线贴图（含缩放）、遮蔽贴图（强度）、自发光；纹理坐标变换 | 透明混合（先按不透明 / alphaMask 处理）、清漆、透射等扩展 |
| 坐标 | glTF Y 向上、米 → Terra Z 向上（绕 X 轴 +90°），单位不变 | — |
| 颜色空间 | 基础色与自发光贴图按 sRGB 解码，其余贴图线性 | — |

**诊断**：文件不存在、JSON 错误、缺失 `.bin` 或贴图（给出 glTF 中的 URI 与解析后的完整路径）、不支持的特性（列出名称），都作为结构化错误或警告返回；缺失贴图时用中性默认值继续加载。

## 5. 渲染侧改动

| 改动 | 说明 |
| --- | --- |
| 纹理 | `Texture2D`（RGBA8 / sRGB8_ALPHA8，完整 mip，三线性 + 各向异性过滤） |
| 材质 | `Material` 增加五张可选贴图与遮蔽强度、法线缩放；着色器按位开关采样 |
| 法线贴图 | 切线空间（顶点切线 + 副切线符号） |
| 环境遮蔽 | 贴图 AO 只作用于环境光（不作用于太阳直射光），并做镜面遮蔽近似 |
| 太阳对齐 | 加载 HDRI 时找出最亮区域的方向与积分亮度，可选“方向光跟随环境贴图的太阳” |
| 资产模块 | 新模块 `terra_asset`（或放入 `terra_render`，见第 8 节）：`loadGltf(path) → AssetResult{场景树、网格、材质、贴图、诊断}`，只用 Terra 类型 |

## 7. 画质路线（真实感，M1-09 之后，按收益排序）

1. 屏幕空间环境遮蔽（GTAO）：接触处变暗，物体“落地”。
2. 级联阴影（大场景）与更柔和的阴影（PCSS）。
3. 泛光、自动曝光。
4. 屏幕空间反射（物体之间的反射）。
5. 透明材质与清漆。

是否以及何时做，在 M1-10（画质与帧耗时基线）时按实际观感再定。

## 11. 实现

| 位置 | 内容 |
| --- | --- |
| `terra/render/image.hpp` | `ImageRgba8`、`loadImage`、`decodeImage`（PNG / JPEG → RGBA8） |
| `terra/render/resources.hpp` | `Texture2D`（RGBA8 或 SRGB8_ALPHA8，完整 mip，三线性，重复寻址） |
| `terra/render/mesh.hpp` | 顶点增加切线（xyz + 手性 w）；`computeTangents`（逐三角形累加 u、v 方向，Gram-Schmidt 正交化）；生成器与 glTF 都使用；`GpuMesh` 增加属性 3 |
| `terra/render/pbr.hpp` | `Material` 增加五张贴图、法线缩放、遮蔽强度、双面；`shade` / `ambientIbl` 增加遮蔽参数（漫反射乘以 AO，镜面乘以 Lagarde 镜面遮蔽，直射光不受影响）；`srgbDecode`；GLSL 同步 |
| `SceneRenderer` | 着色器按位采样五张贴图（单元 5–9）、切线空间法线贴图、双面（不剔除、背面法线取反） |
| `terra/render/hdr_image.hpp` | `extractSun`：找出小而极亮的区域（峰值 ≥ 50 × 平均、阈值以上立体角 < 0.5% 球面），积分为方向光的方向与辐照度，并把这些像素压到阈值 |
| `terra_asset`（新模块） | `loadGltf`：.gltf / .glb、节点层级（`cgltf_node_transform_world`）、Y→Z 换算、8/16/32 位索引、缺失法线（面积加权）与切线生成、pbrMetallicRoughness + 法线 / 遮蔽 / 自发光贴图（按槽位决定 sRGB）、`KHR_materials_emissive_strength`；结构化诊断（不支持的 required 扩展、缺失缓冲区、JSON 错误为错误；used 扩展、纹理变换、缺失贴图、动画、蒙皮、透明等为警告）。`GpuAsset`：贴图与网格上传一次，按摆放生成渲染项 |
| 设置 | `render.sunFromEnvironment`（默认开） |
| `terra_viewer` | 加载三个资产（存在时）放在相机前方地面；环境贴图加载时提取太阳并从贴图中去掉，方向光按环境旋转跟随（亮度 × 环境强度）；“渲染”分组新增“方向光跟随环境贴图中的太阳”，跟随时手动的太阳参数变灰；大纲列出资产 |
