## 2. M2-02：致命错误与紧急保存

**新增 `terra/core/fatal.hpp`（`terra_core`）：**

| 接口 | 说明 |
| --- | --- |
| `registerEmergencySave` / `unregisterEmergencySave` / `ScopedEmergencySave` | 登记紧急保存函数（返回空表示成功，否则返回失败原因），按登记顺序调用；线程安全 |
| `setFatalContext` | 进程级诊断上下文（如“设置文件”），写入报告；值为空时删除该项 |
| `runEmergencySaves` | 依次调用；每个函数的失败与异常都被记录，不影响后续项；记录各自用时 |
| `formatFatalReport` / `formatEmergencyResults` | 报告正文（纯函数，便于测试） |
| `crashDirectory` | 依次取 `$TERRA_CRASH_DIR`、`$XDG_STATE_HOME/terra`、`~/.local/state/terra` |
| `fatalExit` | 打印报告 → 写报告文件 `crash-<时间>-<进程号>.txt` → 紧急保存 → 把保存结果追加到 stderr 与报告 → `exit(70)` |

`fatalExit` 先写报告再做紧急保存：即使某个保存函数卡住，诊断也已经写到磁盘上。如果处理过程中再次出错（第二次进入），直接以 70 退出，不再处理。

**MuJoCo 后端：**
- 加载时用 `mju_setLogHandler` 登记 Terra 的处理函数，只登记一次。
- 错误级消息交给 `fatalExit`。报告附带出错时的状态：世界实例、模型文件、调用（step 或 reset）、出错前已完成的步序号、仿真时间。这些信息来自 step 和 reset 期间设置的线程局部“当前世界”记录。
- 其他级别交回 MuJoCo 默认处理，与 M0 相同：打印到 stderr，不写日志文件。
- 模型编译期间的错误由 MuJoCo 编译器自己的线程内处理函数截获，作为编译错误返回，不会到达这里。M0-08 的 `headless.arena_too_small` 已证明这一点，本次保持不变。

**查看器：**登记“设置”紧急保存：当前设置（含布局）写回设置文件，只写文件，不调用 GL。同时把设置文件路径写入诊断上下文。设置本来就每 1 秒自动保存（M1-14），紧急保存覆盖的是这最后 1 秒内的改动。

**与 M0 的差异：**运行期致命错误的退出码由 1（MuJoCo 默认的 `exit(EXIT_FAILURE)`）改为 **70**。已同步修改：
- Headless 的 `--help` 增加 70 的说明；
- `physics.backend_fatal` 的期望退出码与输出；
- [M0-08 报告](M0-08-scenarios.md)中的说明。

**设计稿第 8 节的两处调整：**
1. 设计稿写的运行期致命错误夹具是“`<size memory>` 过小”。实际做不到稳定触发：MuJoCo 4.0.1 编译模型时会试跑一步，内存不足在编译阶段就被截获为模型错误；要在运行期才溢出，取决于接触数量，难以稳定构造。改为在一次真实的 `step` 中，经 MuJoCo 的控制回调（`mjcb_control`）调用 `mju_error`。这走的是完全相同的错误路径，而且确定可重复。
2. 设计稿写“警告转入 Terra 的诊断”。本次仍按 M0 的方式交给 MuJoCo 默认处理（打印到 stderr）；加载阶段的警告收集随 M2-04 的组合接口一起做，那时警告需要归属到具体实例。

## 3. M2-03：几何体描述（模型描述修订 2）

`terra/data` 新增以下内容，已有字段不变，快照格式不变：
- 标识：`ModelInstanceId`、`GeomId`、`VisualId`。
- 描述：`ModelInstanceDescription`、`GeomShape`、`GeomDescription`、`MeshDescription`。
- `EntityDescription::modelInstance`。
- `ModelDescription` 的 `modelInstances`、`geoms`、`meshes`、按 ID 查找，以及 `kRevision = 2`。

各字段的含义见 [M2-01 设计](M2-01-scene-design.md) 第 5 节和头文件注释。

**后端填写规则：**
- 几何体按 MuJoCo 编译顺序编号，静态几何（属于世界体）的实体为无效 ID。
- 尺寸与局部位姿直接取编译结果：`geom_size`、`geom_pos`、`geom_quat`，均相对 body 坐标系原点。
- 颜色规则与 MuJoCo 自带查看器相同（`engine_vis_visualize.c` 的 `setMaterial`）：用了材质时取材质颜色；几何体颜色不是默认值时以几何体颜色为准。
- `collides` = contype 或 conaffinity 非 0。
- 网格取编译后的顶点与三角形。MuJoCo 可能把网格平移、旋转到惯性主轴，几何体的局部位姿已经相应补偿，测试验证了“编译后顶点 × 局部位姿 = 原始摆放”。
- 直接加载单个 MJCF 时，只有一个模型实例：名字为空，不加前缀，放置位姿为单位变换。所有实体与几何体都属于它。

**新夹具 `assets/tests/geometry_shapes.xml`**，覆盖：
- 每种形状；带偏移与旋转的几何体；
- fromto 写法（竖直与水平胶囊）；
- 材质颜色与自定颜色；
- group 1、2 与不参与碰撞的几何体；
- 四面体网格、静态地面、子实体上的几何体。
