# M3-04b PD 控制层、悬挂模式与快照的执行器状态

> 状态：**已实现并通过基线验证**（2026-11-24，第 3 节）。依据：[M3-04 设计稿](M3-04-motion-design.md) 第 3、4、5 节，评审问题 4、5、6 均按建议。

## 1. 交付

**快照修订 2：**`PhysicsSnapshot::actuators`，每个执行器记录：
- `controls`：控制量，步进之后即这一步所用的值；
- `force`：执行器输出，乘传动比之前。

Headless 的输出格式不变：`contract_revision` 改由 Headless 自己的输出修订号 `kOutputRevision = 1` 给出，M3-07 再定。

**PD 控制层（`terra_simulation`，`pd_layer.hpp`）：**
- 场景文件新增 `controllers`：

  ```json
  "controllers": [{"type": "pd", "actuators": ["go2/*"], "kp": 50, "kd": 0.5}]
  ```
- `actuators` 写执行器全名，或写 `"<实例名>/*"` 表示该实例的全部执行器。
- 场景实例化时校验：
  - 只接受作用于单个转动或滑动关节的力矩执行器，其余逐个报错；
  - 执行器不存在、通配的前缀不存在、同一执行器被两个 PD 层接管：报错；
  - `kp` 必须大于 0；`kd` 不能为负，省略时为 0。
- **计算：**τ = kp (q* − q) − kd q̇；控制量 u = τ / (增益 × 传动比)，再截断到执行器的控制范围。
- **目标：**
  - 还没有目标时，以当时的关节位置为目标，即保持当前姿态；重置之后清除目标。
  - 动作与面板给出的命令如果属于 PD 层，就只更新目标、不直接下发；其余命令原样保留。
  - 动作文件对这些执行器的越界检查改用**关节限位**（`targetRangeFunction()`），关节没有限位时不限制。
- **依赖：**`terra_simulation` 现在依赖 `terra_scene`（使用 `PdAssignment`）。

**悬挂模式：**场景文件中模型实例新增 `"fixedBase": true`，组合时删掉该实例根部 body 的自由关节，基座固定在放置位姿上。
- **关于关键帧：**MuJoCo 只有在模型编译过之后，删除元素时才会按元素保存关键帧的值；未编译时关键帧仍按旧的 qpos 长度，会编译失败。所以顺序是：先编译子模型 → 删除 → 再编译一次（使关键帧不再处于“待定”状态，组合时才能正确加上实例前缀）。删掉的只是自由关节的 7 个值，其余关节的关键帧值保留。
- 没有自由关节的模型写 `fixedBase`：只给警告。

**场景与查看器：**
- `go2.terra-scene.json` 加上 PD 层，`go2/*` 由 kp 50、kd 0.5 接管，参数取自 Menagerie `go2_mjx.xml`。
- 新增 `g1_suspended.terra-scene.json`：G1 固定在离地 0.3 m 处，初始关键帧 `g1/stand`。
- 查看器打开带 PD 层的场景时，把它装到 runner 的每步控制器上，重置时清除目标。执行器面板与动作播放在 M3-04c 完成。
