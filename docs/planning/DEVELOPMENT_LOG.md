## 4. 后续记录规则

状态使用“未开始 → 进行中 → 待验收 → 已验收”。失败或等待条件另记原因，不将“代码已写”直接等同于“已验收”。

每次实质开发、问题修复或阶段验收后追加事件，更新顶部快照及相关任务状态。记录至少包括：

| 字段 | 应记录内容 |
| --- | --- |
| 编号 / 日期 / 类型 | 连续 LOG 编号、实际日期，区分文档、工程、功能、修复、验证和决策 |
| 任务与变更 | 关联 PRD/任务/决策编号，说明实际完成什么、尚缺什么 |
| 文件与提交 | 实际路径及已有提交号；未提交就明确写未提交 |
| 环境与输入 | OS/架构、编译器、依赖精确版本、模型摘要、步长、控制序列与种子 |
| 验证方法与结果 | 实际命令、通过/失败/未执行、适用条件、报告链接；候选指标不能记为成绩 |
| 风险与下一步 | 未关闭问题、失败原因、影响范围和下一个可执行任务 |

实际验证报告在后续开发时存放 `docs/validation/` 并从此处链接。没有实际执行时一律写“未执行”；没有数据时写“未测量”；计划中的模型和命令不能作为已验收证据。阶段进度不使用缺少明确分母的百分比。
