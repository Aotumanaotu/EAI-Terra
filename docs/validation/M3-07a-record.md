# M3-07a 实验记录与复现（记录格式、Headless）

> 状态：**已实现并通过基线验证**（2026-11-24 第三次运行全部通过，第 3 节）。依据：[M3-07 设计稿](M3-07-record-design.md)，2026-11-24 评审通过。

## 1. 交付

**`terra_core`：**`Sha256`、`sha256Hex`、`sha256File`。按 FIPS 180-4 用标准库实现，没有外部依赖，用来在记录中写入场景和动作文件的内容摘要。

**`terra_simulation`（`record.hpp`）：**

| 接口 | 说明 |
| --- | --- |
| `RecordHeader`、`makeRecordHeader` | 记录头：运行环境（Terra 版本与编译器、物理后端、平台、创建时间）；输入（场景 / 动作文件的路径与 sha256、起始关键帧）；物理设置；状态采样间隔；实体、关节、执行器的名字（按 ID 顺序） |
| `RecordWriter` | 逐行写出 `header` / `control` / `state` / `event` / `summary`。`control` **只在控制量变化时写**，并且只列出变化的执行器（评审问题 1） |
| `readRecord` | 读取并校验：第一行必须是记录头；版本过高、格式错误、步序号不递增都报错，并带行号；缺少 `summary` 只警告（如运行被中断）。数值读回后逐位相同；非有限值写成 `null`，读回为 NaN |
| `rerunRecord` | 重新仿真：<br>1. 加载记录中的场景，场景或动作文件的 sha256 不同时只警告；<br>2. 实体、关节、执行器的名字与顺序必须相同，否则报错；<br>3. 物理设置不同时警告；<br>4. 按起始关键帧重置，每步之前下发记录的控制量（其中已包含动作与 PD 层的输出，复现时不再运行它们）；<br>5. 在每个采样点比较位姿，给出最大位置误差、最大转角误差、是否逐位相同，以及第一次超出容差的步 |

**一份记录对应一段连续运行。**查看器中途重置时的处理在 M3-07c 中定（建议自动结束当前记录、另起一份）。

**Headless：**
- `--record <文件>`：与 `--scene` 或 `--motion` 组合使用。状态按 `--sample-every` 采样，stdout 的输出不变。出错时记录 `error` 事件，摘要中的结束原因为 `error`。
- `--rerun <文件> [--tolerance 位置,姿态]`：输出一行 `{"type":"rerun",…}`，包括步数、比较的采样点数、是否逐位相同、最大误差、容差、第一次超出容差的步，以及是否在容差内。
  - 默认容差为 1e-6 m 与 1e-6 rad（评审问题 3）；
  - **新退出码 6：**复现结果超出容差；
  - 记录读不出、场景不能加载或模型不一致时，退出码 4。
- 参数约束：`--rerun` 不能与其他运行参数同用；`--tolerance` 只用于 `--rerun`；`--record` 不能与 `--model`、`--dry-run` 同用。

**体积实测**见第 3 节（Go2 动作，每 10 步采样一次）。

## 3. 验证记录

开发机：未编译、未运行（按约定）。已做的静态检查：
- 变异锚点全部唯一，所有脚本合计 178/178；
- 脚本通过 `bash -n`；
- SHA-256 的期望值用 Python `hashlib` 核对过。

**基线机器第一次运行（2026-11-24）：**
- 测试：71 中 69、99 中 97 通过，失败的是 `record.rerun` 与 `headless.rerun_motion`（都是机械臂场景）；变异 **6/6**。
- 记录体积：
  - 机械臂 900 步（每 10 步采样）：751 行控制量、91 份状态，共 252 KB；
  - Go2 动作 7000 步：7703 行，6.6 MB。
- Go2 记录后复现：701 个采样点逐位相同，但输出的“最大姿态误差”为 1.3e-7。

**分析：**
1. **假的姿态误差。**原先按 2·acos(|a·b|) 计算转角：四元数的模偏离 1 约 1e-15 时，即使两个四元数逐位相同，也会得到 1e-7 量级的结果。Go2 的“逐位相同却有 1.3e-7 姿态误差”就是这个原因。机械臂的浮动基座在转动，四元数的模的偏离更大，改动控制量的测试在第 40 步就“超出容差”，同样是这个假误差，而不是改动本身的影响。
   - **修正：**改为相对四元数 r = conj(a) ⊗ b，角度 = 2·atan2(|r 的向量部分|, |r.w|)。两个四元数逐位相同时，结果恰为 0。
2. **机械臂的复现不逐位相同**，位置误差小于 5e-7 m；Go2 逐位相同。两者的一个区别是：Go2 的 PD 层每步都改变全部 12 个控制量，记录时去重不会跳过任何一个；机械臂的轮速在 1 s、滑动力在 1.5 s 之后保持不变，记录中被去重跳过。原因暂未确定，本次补充诊断：
   - 复现结果给出第一个不逐位相同的采样步，以及该点上的实体与差值（Headless 打印到 stderr）；
   - `record.rerun` 增加对照：同一次运行在内存中保留每步完整的命令（不去重、不经过文件）后复现。若对照逐位相同而文件记录不同，问题在去重或文件往返；若对照也不同，问题在物理推进本身。

**第二次运行（2026-11-24）：**测试结果与第一次相同（69/71、97/99），但诊断说明了原因：
- **复现本身逐位相同。**机械臂没有打印“第一个不逐位相同的采样点”，说明 91 个采样点全部逐位相同。对照（内存中、每步完整命令）同样逐位相同，Go2 也是。所以去重和文件往返都没有问题。
- **失败 1：**测试要求“最大姿态误差恰为 0”。新算法在两个四元数逐位相同时，理论上得 0，但实测 Go2 为 5.6e-17：编译器可能把乘加合并为融合乘加（FMA），使 `a·b − b·a` 这类表达式出现 1e-17 量级的舍入。
  - **修正：**位姿逐位相同的实体不再计算误差，误差恰为 0；不同时才计算。Headless 的 `rerun_motion` 用正则检查 `max_rotation_error:0`，同样因此失败，现在一并解决。
- **失败 2：**测试改动控制量时查找 `"step":30`，没带逗号，先匹配到了第 30 步而不是第 300 步，所以在第 40 步超出容差。这正说明改动被及时发现了。
  - **修正：**改为查找 `"step":300,`。

以上都只是测试和误差计算的问题，记录与复现的实现没有改动。

**第三次运行（2026-11-24）：全部通过。**

- 变异测试 **6/6**，各项发现的检查失败数为 3、4、4、1、1、4。
