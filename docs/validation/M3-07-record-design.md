## 1. 目标

- 把一次仿真运行完整地记录下来，事后可以：
  - **回放**：只读地重现当时的画面；
  - **重新仿真**：重跑一遍，并与记录比较。
- 记录要能说明“这次运行是在什么条件下得到的”：程序版本、物理后端版本、场景和动作文件的内容摘要、物理设置、步长、控制量。

## 2. 记录文件（`*.terra-record.jsonl`）

每行一个 JSON 对象，带 `type` 字段。与 Headless 现有的输出同一风格，可以直接用文本工具查看和比较。

| 记录 | 内容 |
| --- | --- |
| `header`（第一行） | `format: "terra.record"`、`version: 1`；Terra 版本与编译器；MuJoCo 版本；平台（操作系统、CPU 架构）；场景文件路径与 sha256；动作文件路径与 sha256（有时）；模型描述摘要（实体、关节、执行器的名字与顺序）；物理设置（步长、积分器、求解器、迭代次数、容差、重力）；起始关键帧；记录选项（状态采样间隔） |
| `control` | 第 k 步之前下发的控制量：`{"type":"control","step":k,"actuators":[[id, [值…]], …]}`。**只在控制量变化时写**，没有变化的步不写。PD 层的输出也在内，因为它就是实际下发的控制量 |
| `state` | 与 Headless 的 `state` 行格式相同（实体位姿与速度、关节、接触、诊断），按采样间隔写，第 0 步与最后一步总写 |
| `event` | 重置、按关键帧重置、开始 / 停止动作、步进错误（带步序号） |
| `summary`（最后一行） | 总步数、仿真时间、结束原因（正常 / 错误 / 用户停止） |

数值以 `%.17g` 写出，读回后与原值逐位相同。

**体积估计：**以 G1 每 10 步采样一次为例，每秒约 50 行 state、每行约 6 KB，1 分钟约 18 MB。控制只在变化时写；动作播放时控制量每步都在变，每步约 1 KB，1 分钟约 30 MB。需要更小时可以加大采样间隔，或只记录控制量（重新仿真时再算出状态）。

## 3. 两种用法

**回放（只读）：**
- 查看器“文件 → 打开记录…”。读入 state 行，按时间在采样点之间插值显示（M2-06 的插值），不运行物理。
- 时间轴：播放、暂停、拖动、倍速。
- 场景文件用于加载显示资源；如果它的 sha256 与记录不同，给出警告但仍可回放。

**重新仿真（复现）：**
- 加载记录中的场景，检查场景 / 动作文件的 sha256、程序和 MuJoCo 版本；不一致时给出警告。
- 从记录的起始状态（初始或起始关键帧）开始，每一步之前下发记录中的控制量，然后推进。
- 在每个采样点比较位姿，报告最大偏差（位置 m、姿态 rad）与第一次超出容差的步。
- 由 Headless 提供：`terra_headless --rerun <记录文件> [--tolerance 位置,姿态]`，退出码表示是否在容差内。
- **容差：**
  - 同一台机器、同一构建：期望逐位相同，容差 0；
  - 不同机器或不同编译选项：不承诺逐位相同，默认容差为位置 1e-6 m、姿态 1e-6 rad，可以用参数调整。开发计划中写明“不承诺跨平台逐位一致”。

## 4. 记录从哪里产生

| 位置 | 方式 |
| --- | --- |
| Headless | 新参数 `--record <文件>`：与 `--scene`、`--motion` 组合，写出完整记录；stdout 的输出不变 |
| 查看器 | 菜单“仿真 → 开始记录 / 停止记录”，状态栏显示正在记录与文件大小。手动拖动面板、播放动作、重置都会如实记录 |

实现上，在 `SimulationRunner` 中增加一个“记录器”：每步记录实际下发的控制量（包括排队命令、控制器输出、PD 层输出），按采样间隔记录状态。查看器与 Headless 共用。

## 6. 需要评审的问题

| # | 问题 | 建议 | 其他选项 |
| --- | --- | --- | --- |
| 1 | 控制量的记录方式 | 只在变化时记录（按步序号） | 每步都记录（简单，但文件更大） |
| 2 | 状态采样间隔的默认值 | 查看器每 10 步一次（50 Hz，足够平滑回放）；Headless 沿用 `--sample-every` | 每步记录 |
| 3 | 跨机器复现的默认容差 | 位置 1e-6 m、姿态 1e-6 rad，可调 | 只做“同一机器逐位相同”，不提供跨机器比较 |
| 4 | 回放的范围 | M3-07b 做时间轴回放（播放、暂停、拖动、倍速） | 只做 Headless 的重新仿真比较，回放留到以后 |
| 5 | 实验记录是否同时写入 D-112 的 SQLite 索引 | 不在 M3 做；M4 建资源库时，把记录文件的摘要（时间、场景、结果）加入索引 | 现在就引入 SQLite |
