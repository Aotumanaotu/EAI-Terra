# M3-02 机器人描述扩展（模型描述修订 3）

> 状态：**已实现并通过基线验证**（2026-11-23 第二次运行全部通过，第 5 节）。依据：开发计划 10.2 节 M3-02；M3 评审第 3 条（自由站立从 `stand` 关键帧开始）。

## 1. 交付

**数据契约（`terra/data/model_description.hpp`，`kRevision = 3`）：**只增加字段，原有字段和快照格式不变；Headless 的输出格式也不变。

| 类型 | 新增 | 说明 |
| --- | --- | --- |
| `JointDescription` | `limited`、`rangeMin`、`rangeMax` | 限位只对转动关节和滑动关节有意义，单位是弧度或米（D-012） |
| | `axis`、`anchor` | 转动轴或滑动方向，以及关节位置。两者都在**所属实体**的坐标系中，以 body 原点为参考。计划写的是“相对父实体”，这里改用所属实体坐标系，因为这正是 MJCF 中关节的写法 |
| | `damping`、`armature`、`frictionLoss` | 第一个自由度的被动参数 |
| `ActuatorDescription` | `kind` | 取值 `Motor` / `Position` / `Velocity` / `Other`，判定方法见第 2 节 |
| | `gain`、`damping` | Motor 为增益；Position 为 kp 和 kv；Velocity 为 kv |
| | `gear`、`forceLimited`、`forceMin`、`forceMax` | 传动比（第一个分量）和执行器输出的力限 |
| `KeyframeDescription` | `name`、`time` | `ModelDescription::keyframes` 与 `findKeyframe`。`time` 只作记录 |

**物理接口：**新增 `PhysicsWorld::resetToKeyframe(index)`，下标越界时返回 false，状态不变。语义与 `reset` 相同：步序号归 0，开始新的运行代次，清除故障状态。另外，**仿真时间也从 0 开始**，不采用关键帧自带的时间，以保持“第 0 步 ⇔ 时间 0”这一约定（Headless 输出和记录都依赖它）。

**场景文件：**根上新增可选字段 `initialKeyframe`，值为关键帧全名，例如 `"g1/stand"`。
- 载入时，先应用这个关键帧，再计算 glTF 的 `assembly` 对齐，因此“初始姿态”就是关键帧姿态。
- `SceneInstance::homeKeyframe` 记录它的下标。
- 找不到时在 `/initialKeyframe` 报错，并列出场景中所有关键帧；场景没有关键帧时直接说明。

**仿真推进：**`SimulationRunner` 新增 `setHomeKeyframe` 和 `resetToKeyframe`。
- 设置了起始关键帧时，`reset()` 回到该关键帧。
- 两种重置走同一个屏障：清空命令队列、时钟累加器和快照历史。

**查看器：**
- 打开场景时，把场景的初始关键帧设为 runner 的起始关键帧。工具栏“重置”和 Ctrl+R 都回到它。
- 新增菜单“仿真 → 重置到关键帧”，列出全部关键帧，初始关键帧带“（初始）”标记；选择后在日志中记录。
- 自检增加一项：重置后，全部实体位姿与打开时（第 2 帧）逐位相同。

**参考机器人场景：**三个场景都写了初始关键帧，分别为 `g1/stand`、`go2/home`、`stretch3/home`。

## 2. 执行器类别的判定

判定依据是 MuJoCo 编译后的执行器参数（`actuator_dyntype` / `gaintype` / `biastype` / `gainprm` / `biasprm`）。MJCF 的快捷写法 `<motor>`、`<position>`、`<velocity>` 编译后都变成 general 执行器，所以只能这样识别：

| 类别 | 条件 | 控制量的含义 |
| --- | --- | --- |
| Motor | 无动力学、固定增益、无偏置 | 力或力矩（再乘传动比） |
| Position | 无动力学、固定增益、仿射偏置，且 `bias = (0, −kp, −kv)` | 目标位置 |
| Velocity | 无动力学、固定增益、仿射偏置，且 `bias = (0, 0, −kv)` | 目标速度 |
| Other | 其余情况，例如带滤波或积分动力学，或其他增益形式 | 只描述，不解释 |

用 `<general>` 手写、但参数与上面某一类相同的执行器，会归入相应类别，因为两者的物理行为相同。

## 3. 组合场景中的关键帧

- **名字带实例前缀：**MuJoCo 的 `mjs_attach` 会给子模型的关键帧加上前缀，例如 `g1/stand`。
- **自由关节随放置变换：**MuJoCo 把关键帧中自由关节的值当作世界位姿，组合时不会随放置框架一起变换（见 `ScaleKeyframe` 的注释“free joints … are posed in the world”）。不处理的话，放在别处的机器人按关键帧重置后会跳回原点附近。处理方法：组合编译后，对每个属于实例 i 的关键帧（名字以该实例前缀开头），把其中属于实例 i 的自由关节的位置和姿态乘上放置位姿，线速度也一并旋转（角速度在 body 坐标系中，不需要变换）。
- **未给出的值不变换：**关键帧没有给出某个关节的值时，MuJoCo 用 `qpos0` 补齐，而 `qpos0` 已经包含放置位姿。因此与 `qpos0` 逐位相同的值不再变换，避免重复变换。
- **未覆盖的情况：**mocap body 不在处理范围内，参考机器人都没有用到。

**这一节的前提已在基线机器上得到证实：**“MuJoCo 不变换”原本是读源码得出的判断。`physics.robot_description` 用一个放在 (1, 2, 0)、偏航 90° 的实例检验最终结果：第一次运行通过；去掉这段处理（变异“关键帧不随放置变换”）后有 3 项检查失败。

**修正：**测试增加一项：按 `b/rest`（空关键帧）重置后，实例 b 的基座仍在放置后的初值 (1, 2, 0.4)，偏航仍为 90°。原来那项检查改为“其他实例的关键帧不影响它”，予以保留。
