# M4-04 传感器面板与离线采集

> 状态：**已实现，待基线机器验证**（第 6 节）。依据：[M4-01 传感器设计稿](M4-01-sensor-design.md)（2026-11-24 评审通过）第 5、6 节。

## 1. 交付

**采样（查看器）：**
- 每完成一步，以及打开场景、重置之后的初始状态，都按各传感器的频率判断该步是否采样，规则与 Headless 相同（`sensorSampleDue`）：
  - IMU：记入曲线，保留最近 2500 份；
  - 2D 激光雷达：在该步做射线检测；
  - 相机：保存该步的快照，本帧结束前渲染。预览只渲染最新的一份；不丢帧的完整采集用 `terra_capture`。
- 实验记录与传感器共用一个常驻的“每步观察者”，开始、停止记录时不再替换它。
- 回放期间不推进物理，传感器也不更新；传感器的记录在 M4-07。

**“传感器”面板（`###Sensors`）：**默认与详情、执行器同在右侧一组；已保存的布局中没有它时，首次显示并入执行器面板所在的组。窗口菜单可以开关。
- **IMU：**选择 IMU；最新的比力与角速度；两张曲线（x 红、y 绿、z 蓝，纵轴自动缩放）；频率、采样次数、时间。
- **2D 激光雷达：**俯视图。雷达在中心，朝上为雷达的 0°，每 1 m 一圈；红点为命中，灰线为没有命中，蓝点为近于最小量程。旁边标出命中数。
- **相机：**彩色与深度伪彩色（近红远蓝）并排；鼠标悬停显示该像素的深度；标出分辨率、视场角、频率、步序号与时间。
- 场景中没有传感器时，提示在场景文件的 `sensors` 中添加。

**`terra_capture`（新程序）：**
```
terra_capture (--scene <场景> | --motion <动作> [--scene <场景>]) (--steps N | --duration 秒) --output <目录>
              [--no-cameras] [--force] [--expect-renderer 子串]
```
- 输出目录：
  - `capture.json`：场景、动作、步长、步数、各传感器的参数，相机含内参；
  - `sensors.jsonl`：IMU 与雷达，格式与 Headless `--sensors` 的行相同；
  - `cameras/<相机名>/frames.jsonl`：每帧的步序号、时间、相机位姿与文件名；
  - `rgb/<步序号>.png`；
  - `depth/<步序号>.npy`：float32，米；NumPy 格式，Python 中 `numpy.load` 直接读取。
- 只在场景中有相机、且没有给 `--no-cameras` 时创建隐藏窗口作为图形上下文；否则不创建任何图形资源，没有显示服务器也能运行。
- 已有结果时拒绝覆盖。`--force` 只删除本程序写的文件。
- 光照为默认画质与半球光（与查看器的默认设置相同）。场景文件中的 `view.environment` 暂不使用。

**Stretch 3 场景：**加上真机就有的头部相机（MJCF 中的 `d435i_camera_rgb`，640 × 480，15 Hz，0.1～10 m）与底盘雷达（装在 `laser` 实体上，360 束、0.15～12 m、10 Hz）。不影响物理与参考图。

**小工具（只用 Python 标准库）：**
- `scripts/sensors/npy_center.py`：读 `.npy`，打印尺寸、中心深度与范围；
- `scripts/sensors/plot_lidar.py`：M4-03b 已有，也可读 `sensors.jsonl`。

## 4. 已知的限制

- 查看器中的相机预览每帧最多渲染每个相机的最新一份。追赶时中间的帧不渲染；完整的序列用 `terra_capture`。
- 相机在查看器中按显示的频率渲染，会占用 GPU 时间。分辨率高、相机多时，帧率会下降；渲染耗时目前没有单独计入统计面板。
- `terra_capture` 不使用场景文件的 `view.environment`，只用半球光。

**用户反馈：**
1. **相机的画面像是反了，应逆时针转一下。**按模型推算，Stretch 3 的头部 D435i 是横着装的：在机器人坐标系中，图像的“上方”指向水平方向，“右方”才是竖直向上。真机的图像同样需要转 90° 才正，所以仿真的数据是对的。处理：场景文件的相机新增 `displayRotationDeg`（0、90、180、270，逆时针），**只影响显示**，图像、深度与内参不变（与真机一致）。Stretch 3 场景设为 90；`capture.json` 记下 `display_rotation_deg`。面板按旋转后的四个角贴图，悬停取深度用同一个换算（`terra::scene::displayToImage`）。
2. **远处有黄色的光，可能是环境的问题。**我没有看到图片。最可能的原因：默认太阳是暖白色（方位 150°、高度 50°），照在 Stretch 场景有一定光泽的地面上形成偏黄的高光，视口中也会有。另外，原来的深度伪彩色配色中间一段颜色叠成白、黄色，也可能被看成“黄光”。已把深度配色改为分段线性的红 → 橙 → 绿 → 青 → 蓝 → 深蓝。是否还要调整光照，等用户确认黄光在彩色图还是深度图里。
