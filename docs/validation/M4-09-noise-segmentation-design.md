> - **雷达参数查真实的数据手册，不凭空给值**：见 2.4 节（预设）。

> - [M4-01 传感器设计稿](M4-01-sensor-design.md)：P0 的传感器都是无噪声的真值；噪声在 P1 中由 Terra 显式添加，带种子、可复现（MuJoCo 的 `noise` 属性只是记录，MuJoCo 自己不加）。

## 1. 目标与验收

| 目标 | 验收 |
| --- | --- |
| IMU、2D 激光雷达、深度与 RGB 相机可以配置噪声；写在场景文件中，带种子 | 同一场景、同一种子两次运行（含 Headless、查看器、`terra_capture`、复现 `--rerun`）读数**逐位相同**；换种子结果不同 |
| 噪声的统计性质正确 | 大量样本的均值、标准差、零偏随机游走的增长（√t）与配置一致，误差在统计容差内（阈值冻结） |
| 真值仍然可用 | 关掉噪声（全局开关）得到的读数与现在逐位相同；记录中写明噪声配置 |
| 所有出口一致 | Headless `--sensors`、查看器传感器面板、`terra_capture`、实验记录、ROS2 发布看到的是**同一份**带噪声的读数（不会各加一次） |
| 分割图：相机可以输出每个像素属于哪个实体 | 已知场景中像素的实体 ID 与几何计算一致；ID 与实体名的对照表随图像给出；整数、逐位可复现 |
| 分割图的出口 | 查看器预览（按 ID 着色）、`terra_capture` 写 16 位 PNG 与对照表、ROS2 发布图像与对照表、记录（与相机图像相同的方式） |

## 2. 噪声

### 2.1 模型

| 传感器 | 参数 | 说明 |
| --- | --- | --- |
| IMU（加速度计、陀螺仪各一组） | `noiseDensity`（白噪声密度）、`randomWalk`（零偏随机游走）、`bias`（初始零偏，固定值或按标准差随机取） | 与 Kalibr、IMU 数据手册相同的连续时间参数；按采样频率离散化：单个样本的白噪声标准差 σ = 密度 × √频率，零偏每个样本走 σ_b × √Δt |
| 2D 激光雷达 | `rangeStd`（距离高斯噪声，米）、`rangeStdRelative`（与距离成正比的部分，三角测距雷达的特点）、`dropout`（每束丢失的概率，丢失为 inf）、`resolution`（距离量化，米） | 只加在命中的束上；σ = rangeStd + rangeStdRelative × 距离；结果截断到 [rangeMin, rangeMax]，超出时为 inf |
| 深度相机 | `depthStd`（固定部分）与 `depthStdQuadratic`（与距离平方成正比的部分，双目深度的典型模型 σ = a + b·z²）、`dropout`（像素丢失概率） | 16UC1 输出时再量化为毫米（已有） |
| RGB 相机 | `pixelStd`（每个通道的高斯噪声，0～255） | 截断到 0～255 |

其他：
- 噪声都可以单独关闭（不写即为 0）。
- 以后增加的模型（例如 IMU 的比例因子与轴间误差、雷达的角度抖动）作为新的可选字段，不改变已有字段的含义。

### 2.2 写法（场景文件）

```json
"noise": {"seed": 42},
"sensors": [
  {"type": "imu", "name": "go2/imu", "site": "go2/imu",
   "noise": {"gyro":  {"noiseDensity": 1.7e-4, "randomWalk": 2.0e-5, "bias": {"std": 0.002}},
             "accel": {"noiseDensity": 2.0e-3, "randomWalk": 3.0e-3}}},
  {"type": "lidar2d", "name": "tb4/scan", "entity": "tb4/rplidar_link",
   "noise": {"rangeStd": 0.01, "dropout": 0.002, "resolution": 0.001}},
  {"type": "camera", "name": "tb4/oakd", "entity": "…",
   "noise": {"depthStd": 0.002, "depthStdQuadratic": 0.003, "dropout": 0.01, "pixelStd": 2.0}}
]
```

- 场景级的 `noise.seed`：没有时为 0。
- 每个传感器的随机数由 (seed, 传感器全名, 步序号, 分量) 唯一决定，用计数器式的随机数生成器（如 SplitMix64 或 Philox），读数与采样顺序、程序无关。
- 只有零偏随机游走需要状态：从初始状态开始逐样本推进；重置、按关键帧重置时回到初始状态。
- **关闭噪声（用户评审时的要求）**，三个层次，任一处关闭即为真值：
  - 每个传感器：`"noise": {"enabled": false, …}`（参数保留，只是不加）；
  - 场景：`"noise": {"seed": 42, "enabled": false}`；
  - 运行时：Headless 与 `terra_capture` 用 `--no-noise`；查看器的传感器面板有“噪声”开关（只影响本次运行，便于与真值对照），状态栏标出当前是否加噪声；
  - 实验记录的头部写明本次是否加了噪声，复现时按记录中的设置。

### 2.3 一份读数，所有出口共用

现在雷达的射线检测在查看器、桥接、Headless 中各自调用。加噪声后若各自用顺序随机数，同一时刻的读数在 ROS2 与面板中会不同。

**实现（与评审时的写法不同，目的相同）：**
- 噪声是步序号的确定函数：白噪声、丢失、量化只取决于 (种子, 传感器, 步序号, 分量)；
- 随机游走只取决于“到这一步为止的各个采样步”，按步序号重算或累加，结果相同；
- 因此各出口各自持有一个噪声对象（`terra::simulation::SensorNoise`），同一步的读数**逐位相同**，不需要重构为一个共用的采样器；
- `simulation.sensor_noise` 检查两个独立的噪声对象、不同调用顺序得到逐位相同的读数。

相机的噪声在图像渲染出来之后加，只加一次（查看器中预览、记录与 ROS2 用同一份；`terra_capture` 写文件前加）。

### 2.4 雷达预设（按数据手册，用户评审时的要求）

传感器可以写 `"noise": {"preset": "rplidar_a1m8"}`，从 `assets/sensors/lidar_presets.json` 取参数；显式写的字段覆盖预设。预设文件逐项写明数据手册的原文数值、出处与换算方法。

| 预设 | 数据手册的数值 | 换算为噪声参数 |
| --- | --- | --- |
| `rplidar_a1m8`（SLAMTEC RPLIDAR A1M8，TurtleBot 4 所用；三角测距） | 距离 0.15–12 m（A1M8-R5 起；R4 及以前 0.15–6 m）；距离分辨率 < 0.5 mm（1.5 m 以内）、全量程 < 1% 距离；采样频率 8010 Hz；扫描频率 1–10 Hz，典型 5.5 Hz（数据手册 v2.1，2018-02-05） | 手册只给分辨率，没有标准差：`resolution` 取 0.0005 m；`rangeStdRelative` 取 0.01 / 3（把“< 1%”视为 ±3σ 的上界，**换算假设**，可覆盖） |
| `hokuyo_ust10lx`（Hokuyo UST-10LX；飞行时间） | 检测距离 0.06–10 m（白色肯特纸）；精度 ±40 mm；重复精度 σ < 30 mm（工厂标准测试条件，白色肯特纸）；角分辨率 0.25°，270°，扫描 25 ms（40 Hz） | `rangeStd` 取 0.03 m（手册直接给出的 σ 上界） |
| `rplidar_s2`（SLAMTEC RPLIDAR S2；直接飞行时间） | 距离 0.05–30 m（90% 反射率）、0.05–10 m（10% 反射率）；精度 ±30 mm；距离分辨率 13 mm；角分辨率 0.1125°；采样 32000 次/秒；扫描 10 Hz | 手册只给精度范围：`rangeStd` 取 0.01 m（把 ±30 mm 视为 ±3σ，**换算假设**，可覆盖）；`resolution` 取 0.013 m |

出处（2026-11-25 查阅）：
- RPLIDAR A1M8：SLAMTEC 数据手册 A1M8 v2.1（Adafruit 转载 https://cdn-shop.adafruit.com/product-files/4010/4010_datasheet.pdf ；官方地址 http://bucket.download.slamtec.com/b90ae0a89feba3756bc5aaa0654c296dc76ba3ff/LD108_SLAMTEC_rplidar_datasheet_A1M8_v2.2_en.pdf ）；
- Hokuyo UST-10LX：北阳电机产品页 https://www.hokuyo-aut.jp/search/single.php?serial=167 、规格书 https://www.hokuyo-aut.jp/dl/UST-10LX_Specification.pdf ；
- RPLIDAR S2：SLAMTEC 参数页 https://www.slamtec.com/en/s2/spec 。

**说明：**
- 预设只给噪声参数，不改雷达的束数、频率与量程（那些在传感器本身的字段里）；
- 数据手册的数值在白色目标、标准条件下测得，实际环境（深色、斜射、阳光）误差更大；
- 换算假设在预设文件中逐项标注。
- TurtleBot 4 配方中的雷达暂定 1080 束、8 Hz（M4-08b 问题 5，待真机核对）。按 A1M8 手册，8010 Hz ÷ 8 Hz ≈ 1000 束，与暂定值接近，本步不改。
- IMU 没有预设：没有查到参考机器人所用 IMU 的型号与手册，示例与测试中使用的参数在场景文件中注明“测试值”。

### 2.5 记录与复现

- 实验记录的头部写入噪声配置与种子；
- 记录中保存带噪声的读数（机器人“看到的”）；
- 复现时按同一配置重算，逐位比较；
- 真值不另存：用 `--rerun --no-noise` 可以得到。

## 3. 分割图

| 部分 | 做法 |
| --- | --- |
| 写法 | 相机传感器新增 `"segmentation": true` |
| 内容 | 每个像素为**实体 ID**（与模型描述中的实体编号相同）；0 为背景（没有命中，或命中的是没有绑定实体的静态装饰）。另给对照表：ID → 实体全名、模型实例名 |
| 渲染 | 渲染模块新增 ID 渲染（与深度渲染相同的方式）：渲染项带一个整数 ID，平涂写入 32 位整数目标；不做多重采样，像素中心取值；半透明叠加不写入 |
| 语义类别（可选） | 场景文件中给模型实例或实体名的通配写类别（`"labels": {"go2/*": "robot", "floor": "ground"}`），对照表中附上类别；本步只给出对照，不另出一张类别图（类别图可由对照表直接换算） |
| 查看器 | 传感器面板中按 ID 着色显示（固定的配色表，相同 ID 颜色不变）；悬停显示实体名 |
| `terra_capture` | 每帧写 `cameras/<相机>/seg/<步序号>.npy`（uint16，与深度同为 NumPy 格式；stb 不能写 16 位 PNG；ID 超过 65535 时报错）与一次 `cameras/<相机>/seg_labels.json` |
| ROS2 | `/<相机>/segmentation/image_raw`（`sensor_msgs/Image`，编码 `16UC1`）；对照表发布在 `/<相机>/segmentation/labels`（`std_msgs/String`，JSON，transient local，只发一次）。不引入 `vision_msgs`（问题 5） |
| 记录 | 本步不保存（实验记录的相机图像由用户选择保存；分割图以后随需要加入） |

## 4. 实现概要

| 部分 | 位置 |
| --- | --- |
| 噪声模型、随机数、采样器 | `engine/simulation`（新文件 `sensor_noise.*`、`sensor_sampler.*`，不依赖图形） |
| 场景文件的 `noise`、`segmentation`、`labels` | `engine/scene` |
| ID 渲染 | `engine/render`（新文件 `id_renderer.*`）；`RenderItem` 增加 `id` |
| 出口改为取采样器的读数 | Headless、查看器、`terra_capture`、ROS2 桥接、记录 |
| 相机噪声与分割图的出口 | `apps/viewer/camera_sensor.*`、`apps/capture`、ROS2 桥接 |

## 5. 测试

| 测试 | 内容 |
| --- | --- |
| `simulation.sensor_noise`（新） | 预设文件的读取与覆盖；三个层次的关闭；随机数可复现（同种子相同、换种子不同、与调用顺序无关）；白噪声的均值与标准差、随机游走的方差随时间线性增长（10⁵ 个样本，统计容差冻结）；雷达丢失率与量化；深度噪声的 a + b·z² 模型；重置后随机游走回到初值 |
| `scene.file`（扩充） | `noise`、`segmentation`、`labels` 的读取与严格校验 |
| `headless.sensors_noise`（新） | 同一场景两次 `--sensors` 输出逐字节相同；`--no-noise` 与没有噪声的场景逐字节相同；换种子不同 |
| `headless.rerun_sensors`（扩充） | 带噪声的记录复现逐位相同 |
| `graphics.segmentation`（新） | 已知场景（方块、球、地面）：像素中心的 ID 与按几何计算的结果一致；两次渲染逐位相同；对照表正确 |
| `graphics.capture_determinism`（扩充） | 带噪声的图像与分割图两次采集逐字节相同 |
| `ros2.bridge_headless`（扩充） | 带噪声时 ROS2 收到的 IMU 与 Headless 输出的同一步读数逐位相同（一份读数共用） |
| `graphics.viewer_sensor_selftest`（扩充） | 面板中的噪声开关；分割图预览 |
| 变异（约 8 个） | 例如：<br>· 随机数与步序号无关；<br>· 白噪声没有按频率离散化；<br>· 随机游走不累积；<br>· 噪声加了两次；<br>· 雷达丢失没有置为 inf；<br>· 分割图把背景写成 1；<br>· 重置不回到初值；<br>· `--no-noise` 不生效 |

**展示：**
- 查看器打开 Go2 或 TurtleBot 4，传感器面板中打开、关闭噪声，对照 IMU 曲线；
- 相机的分割图预览；
- RViz2 中看带噪声的 `/scan`。

## 6. 需要用户准备

不需要新的软件或素材。

如果手边有真机 IMU 或雷达的数据手册（或 Kalibr 标定结果），可以提供参数，作为参考机器人的默认噪声；没有时只在测试与示例场景中使用典型值。

## 7. 不在本步

- 3D 激光雷达（MID-360、L1 的非重复扫描）：递延到 M5（用户 2026-11-25 同意）；
- 相机的运动模糊、镜头畸变、自动曝光；
- IMU 的比例因子与轴间误差、温度漂移（以后作为可选字段增加）；
- 语义类别图（由对照表换算，见第 3 节）。

## 8. 需要评审的问题

| # | 问题 | 建议 | 其他选项 |
| --- | --- | --- | --- |
| 1 | IMU 噪声的参数形式 | 连续时间的噪声密度与随机游走（Kalibr、数据手册的写法），按采样频率离散化 | 直接给每个样本的标准差（简单，但换采样频率后含义改变） |
| 2 | MJCF 中的 `noise` 属性 | 不自动使用（MuJoCo 自己也不用），打开场景时在诊断中列出，提示可以写进场景文件 | 自动当作白噪声使用 |
| 3 | 随机数的组织 | 计数器式：由 (种子, 传感器, 步序号, 分量) 唯一决定，与调用顺序、程序无关；只有随机游走带状态 | 每个传感器一个顺序生成器（简单，但读数依赖调用顺序，各程序之间难以逐位一致） |
| 4 | 读数只产生一次 | 新增传感器采样器，面板、记录、ROS2、Headless 共用同一份读数 | 各出口各自调用并加噪声（会不一致，随机游走被推进多次） |
| 5 | 分割图在 ROS2 中的格式 | `16UC1` 图像加 JSON 对照表（`std_msgs/String`，transient local），不增加依赖 | 用 `vision_msgs/LabelInfo`（标准但多一个依赖包） |
| 6 | 分割图的 ID | 实体 ID（与模型描述一致，最细）；语义类别由对照表给出 | 只按模型实例着色（粒度粗，看不出部件） |
| 7 | 记录中存什么 | 带噪声的读数与噪声配置；真值用 `--rerun --no-noise` 重算 | 真值与带噪声的读数都存（文件大一倍） |
