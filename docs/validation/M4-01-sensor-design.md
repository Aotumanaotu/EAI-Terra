# M4-01 传感器设计稿

> 状态：**草案，待评审**（2026-11-24）。依据：开发计划 11.2 节 M4-01～M4-04、11.3 节评审结论（IMU 用 MuJoCo 传感器；图像传感器只在有图形上下文的程序中运行）、11.6 节（TurtleBot 4，2D 激光雷达提前到 P0）。
> ROS2 桥接与 Sim-to-Real 的通信配置另写设计稿（M4-05），本稿只定义传感器本身。

## 1. 范围

| 传感器 | 优先级 | 计算方式 | 需要图形上下文 |
| --- | --- | --- | --- |
| IMU（加速度计、陀螺仪、姿态） | P0 | MuJoCo 自带传感器（`accelerometer`、`gyro`、`framequat`） | 否 |
| 2D 激光雷达 | P0（由 P1 提前） | MuJoCo 射线检测 `mj_multiRay` | 否 |
| RGB 与深度相机 | P0 | Terra 渲染器离屏渲染并读回 | **是** |
| 3D 激光雷达（MID-360、L1 的扫描图案）、分割图、噪声 | P1 | 见开发计划 M4-09 | 视类型 |

**P0 的读数都是无噪声的真值。**MJCF 中的 `noise` 属性 MuJoCo 不会施加（G1 的 IMU 写了 noise），Terra 也不施加；噪声在 P1 中显式添加，带种子、可复现。

## 2. 传感器从哪里来

**1）MJCF 中已有的：**

| 来源 | 处理 |
| --- | --- |
| 同一安装点（site）上的 `accelerometer` + `gyro`（可再加 `framequat`） | 自动组成一个 IMU，名字取安装点名（带实例前缀，如 `g1/imu_in_pelvis`），默认启用，频率等于物理频率 |
| `<camera>` | 列入相机清单，**默认不启用**（渲染开销大）；场景文件引用它的名字即可启用 |

参考机器人中：G1 有两个 IMU（骨盆、躯干），Stretch 3 有一个 IMU 与 5 个相机，Go2 只有安装点 `imu`、没有传感器。

**2）场景文件新增 `sensors`：**

```json
"sensors": [
  {"name": "go2/imu", "type": "imu", "site": "go2/imu", "rateHz": 500},
  {"name": "head_rgbd", "type": "camera", "camera": "stretch3/d435i_camera_rgb",
   "width": 640, "height": 480, "rateHz": 30, "rgb": true, "depth": true},
  {"name": "g1/head_cam", "type": "camera", "entity": "g1/torso_link",
   "position": [0.08, 0, 0.45], "rotation": {"rpyDeg": [0, 20, 0]},
   "width": 640, "height": 480, "fovyDeg": 58, "near": 0.1, "far": 10, "rateHz": 30},
  {"name": "base_scan", "type": "lidar2d", "entity": "turtlebot4/rplidar_link",
   "angleMinDeg": -180, "angleMaxDeg": 180, "samples": 720, "rangeMin": 0.15, "rangeMax": 12, "rateHz": 10}
]
```

- 安装方式三选一：`site`（MJCF 中的安装点）、`camera`（MJCF 中的相机），或 `entity` + 相对位姿。
- 给实体加 IMU 时，组合模型时插入安装点与三个 MuJoCo 传感器（与 `mjs_attach` 同一流程）。因此，加 IMU 会改变模型，但不改变动力学：MuJoCo 的传感器只读状态。
- 错误按场景文件现有的方式报告：JSON 指针 + 原因；找不到实体、安装点或相机时，列出可选项。

## 3. 数据契约

**模型描述修订 6**（只增加字段）：

| 类型 | 字段 |
| --- | --- |
| `SensorDescription` | `id`、`name`、`kind`（Imu / Camera / Lidar2D）、`mount`（实体 ID）、`mountPose`（在实体坐标系中）、`rateHz`；按类型的参数：相机的宽、高、`fovy`、`near`、`far`、是否输出 RGB 与深度；雷达的角度范围、采样数、距离范围 |
| `ModelDescription::sensors` | 全部已启用的传感器 |
| `ModelDescription::cameras` | MJCF 中的全部相机（名字、实体、局部位姿、`fovy`），无论是否启用 |

**快照修订 3：**`PhysicsSnapshot::sensors`，即**本步采样了的**物理侧传感器的读数（`id` + 数值）。IMU：加速度（m/s²）3 个、角速度（rad/s）3 个、姿态四元数（wxyz）4 个；2D 雷达：每束的距离（m）。

**相机帧**不进快照（图像大，且由渲染侧生成）。单独的类型 `CameraFrame`：

| 字段 | 说明 |
| --- | --- |
| `sensor`、`step`、`time`、`runEpoch` | 与快照相同的时间标识 |
| `pose` | 相机在世界中的位姿（Terra 相机坐标系，见第 4 节） |
| `intrinsics` | `width`、`height`、`fx`、`fy`、`cx`、`cy`（像素，光学坐标系）；畸变为 0 |
| `rgb` | 8 位 RGB，按行从上到下 |
| `depth` | 32 位浮点，**米**，沿光轴的距离（不是到光心的直线距离）；没有命中为 `+inf`（ROS REP-117 的约定）。ROS 输出时按通信配置转换（如 RealSense 的 16 位毫米、0 表示无效） |

**后端接口（`PhysicsWorld`）新增：**
- 物理侧传感器的读数随快照给出；
- `castRays(origin, directions, maxRange, filter)`：返回每条射线的距离，供雷达使用。保持后端无关：射线检测是一般的几何查询，以后别的后端也有。

## 4. 坐标与时间

**坐标系：**

| 对象 | 约定 |
| --- | --- |
| 世界 | Terra 约定不变：右手，Z 向上，X 向前（D-012） |
| IMU | 安装点的坐标系。静止水平放置时，加速度计读数为 (0, 0, +9.81)（比力：重力反方向），与真机 IMU 和 ROS 的 `sensor_msgs/Imu` 一致 |
| 2D 雷达 | 安装坐标系的 XY 平面，角度从 +X 起逆时针为正（与 `sensor_msgs/LaserScan` 一致） |
| 相机（Terra） | 与 MuJoCo 和 OpenGL 相同：看向 −Z，+Y 向上，+X 向右 |
| 相机（光学） | ROS 约定：看向 +Z，+X 向右，+Y 向下。由 Terra 相机坐标系绕 X 轴转 180° 得到。内参按光学坐标系给出；ROS 桥接为每个相机发布这两个坐标系 |

**采样时刻：**传感器在**物理步之后**采样，时间戳 = 该步的仿真时间与步序号。图像也按采样那一步的快照渲染，**不使用**显示帧的插值姿态。因此，图像、IMU 与关节状态可以按步序号精确对应。

**采样频率**见第 8 节问题 1。

## 5. 各程序中的可用性

| 程序 | IMU、2D 雷达 | 相机 | 说明 |
| --- | --- | --- | --- |
| Headless | 有 | **无** | 仍不链接任何图形库；场景中有相机时提示“相机在 Headless 中不可用”，其余照常运行 |
| 查看器 | 有 | 有 | 新增“传感器”面板：IMU 曲线、雷达俯视图、相机画面（彩色与伪彩色深度） |
| **`terra_capture`（新）** | 有 | 有 | 有图形上下文、不开界面：按场景与动作运行，把读数和图像写入目录；用于数据采集与测试 |

**相机的图形上下文：**先用隐藏窗口（GLFW，不显示），需要 X 或 Xvfb，与现在的图形测试相同。不需要显示服务器的 EGL 方式作为 P1。

**关闭图像传感器：**场景中没有启用的相机，或用 `--no-cameras` 关闭时，不创建离屏目标与读回缓冲。

**查看器中的时序：**每帧推进若干步，步观察者在相机该采样的步上保存快照；本帧结束前逐个渲染这些快照。追赶时一帧可能要渲染多张；为保证可复现，不丢帧，渲染耗时计入统计面板。

## 6. 输出格式

**Headless：**新增 `sensor` 行（JSON Lines，与 `state` 行并列）：`{"type":"sensor","name":"go2/imu","step":…,"time":…,"values":[…]}`。是否输出用 `--sensors` 控制，默认不输出，以保持原有输出不变。

**`terra_capture` 的输出目录：**

```
<输出目录>/
  capture.json                 场景、动作、传感器清单与内参、程序与后端版本
  sensors.jsonl                IMU、雷达的读数（每行一个采样）
  cameras/<相机名>/frames.jsonl 每帧的步序号、时间、位姿
  cameras/<相机名>/rgb/<步序号>.png
  cameras/<相机名>/depth/<步序号>.npy   float32，米（NumPy 格式，Python 直接读取）
```

PNG 由已有的 `stb_image_write` 写出；`.npy` 格式很简单（文件头 + 原始数据），自己写出，不引入依赖。

## 7. 测试（真值场景）

| 传感器 | 夹具 | 判据（初值，实测后冻结） |
| --- | --- | --- |
| IMU | 水平静止 | 加速度 = (0, 0, 9.81)，角速度 = 0 |
| | 倾斜 30° 静止 | 加速度按姿态旋转后的重力 |
| | 绕竖直轴匀速转动（速度执行器 2 rad/s） | 角速度 z = 2 rad/s；安装点离轴有距离时，加速度包含向心加速度 ω²r |
| | 自由落体（无接触） | 加速度 ≈ 0 |
| | Go2 场景文件加 IMU | 与 G1 自带 IMU 的同类读数一致；姿态与基座实体姿态一致 |
| 2D 雷达 | 4 m × 4 m 的方形房间，雷达在中心 | 0°、90°、180°、270° 的距离等于到墙的距离；45° 方向等于到角的距离；房间外的射线为 `+inf` |
| 相机 | 正对 2 m 外的墙 | 深度 = 2 m；像素中心的深度误差小于设定容差 |
| | 已知位置的方块 | 角点投影的像素坐标与按内参计算的一致（±0.5 像素） |
| | 时间 | 每帧记录的位姿与同一步的快照逐位相同 |
| 全部 | 同一输入运行两次 | IMU 与雷达读数逐位相同；图像逐像素相同（同一机器、同一驱动） |
| 关闭 | 不启用相机 | 不创建任何离屏目标（查询 GL 资源数） |

参考机器人：G1、Stretch 3 自带的 IMU 与相机，在站立与动作中各检查一次读数是否合理（静止时加速度模长约 9.81，相机画面不全黑）。

## 8. 需要评审的问题

| # | 问题 | 建议 | 其他选项 |
| --- | --- | --- | --- |
| 1 | 采样频率怎样落到物理步上 | **按时间累计**：第 k 步满足 ⌊k·Δt·f⌋ > ⌊(k−1)·Δt·f⌋ 时采样。平均频率正好是 f（500 Hz 物理、30 Hz 相机时，间隔在 16 与 17 步之间交替），可复现。Sim-to-Real 要求频率与真机相同，因此不取整 | 固定每 N 步采样一次：间隔均匀，但频率被取整（30 Hz 变成 29.41 Hz） |
| 2 | MJCF 中的相机是否自动启用 | 不自动启用，只列出；场景文件引用名字后启用（渲染开销大）。MJCF 中的 IMU 自动启用（几乎没有开销） | 全部自动启用 |
| 3 | 深度图的内部格式 | float32、米、沿光轴；没有命中为 `+inf`；ROS 输出按通信配置转换 | 16 位毫米（与 RealSense 相同，但精度和量程受限） |
| 4 | 雷达射线打到哪些几何体 | 默认打到参与碰撞的几何体（Menagerie 的碰撞几何在第 3 组），与物理一致；每个雷达可以改为打到显示用的几何体（更接近真实外形，但网格较多时较慢） | 只打显示用的几何体 |
| 5 | 离线采集程序 | 新程序 `terra_capture`，与查看器共用渲染与场景代码，不带界面 | 给查看器加一个不开窗口的模式（查看器会越来越复杂） |
| 6 | 拆分 | M4-02 IMU（含数据契约、场景文件的 `sensors`、Headless 输出）→ M4-03a 离屏渲染与相机 → M4-03b 2D 雷达 → M4-04 传感器面板与 `terra_capture` | 相机与雷达合在一个工作包 |
