## 3. 关键验证结论（M4 统一验收）

- **测试：**

| 构建 | 结果 |
| --- | --- |
| 渲染关闭 | 109/109 |
| 渲染开启 | 149/149 |
| 含 ROS2 | 164/164 |
| ASan | 118 + 31 + 15，全部通过 |
| 重复运行 | 每项至多 3 次，全部通过 |

- **变异测试：**315/315 被发现（M0～M4 全部脚本）。
- **依赖边界：**
  - Headless 不链接图形库；
  - 任何程序都不在构建时链接推理库；
  - 核心模块不含图形、界面、MuJoCo、ROS2 头文件；
  - 测试与验收不在用户目录建库。
- **完成标准：**
  - 真值场景验证传感器；
  - 外部 ROS2 示例闭环；
  - 禁用图像与 ROS2 后纯物理可运行；
  - 图像采集与 Headless 的区分；
  - 传感器与 Go2 策略两次运行逐位相同，记录复现逐位相同。
- **真实 GPU（RTX 5060）：**
  - 自检全部通过；
  - 采集两次逐字节相同；
  - Go2 策略 10 s：5005 步，过载 0 次。

## 4. 下一步：M5 范围

按[开发计划](DEVELOPMENT_PLAN.md)第 5 节，M5 要先冻结一个工业任务及规模，再定任务分解。已有的输入：

1. **强化学习训练的接入**（开发计划 11.9 节，用户已定顺序，训练框架以后再选）：
   - 第 1 层：训练结果回流与评估，即不同噪声、摩擦、延迟下的指标与 sim2sim 差别报告；
   - 第 2 层：一键启动外部训练；
   - 第 3 层：Python 接口（D-110）。
2. 3D 激光雷达（MID-360、L1）。
3. 资源库卡片交互的推敲（11.8 节）。
4. 同名关节、不同机器人的区分（M4-10b 报告第 6 节）。
5. 后续想法：类游戏的物体库拖放摆放（PRD F-M5-05）。

## 5. 保留风险与边界

| 事项 | 说明 |
| --- | --- |
| 可复现的范围 | 只在同一机器、同一构建上逐位可复现；跨机器按容差比较 |
| 单线程推进（D-106） | 复杂场景或多机器人时可能影响实时性 |
| 环境与基准 | 只验证了 Ubuntu 22.04 / x86-64 / X11；像素基准依赖 Mesa llvmpipe 的版本 |
| 许可与 CI | 项目许可证（D-109）待定；CI 未接入 |
