# M3-04 / M3-05 控制界面、动作文件与 Headless 一致性：设计稿

> 状态：**评审通过**（2026-11-24，用户：第 9 节 6 个问题全部同意建议）。依据：开发计划 10.2 节 M3-04、M3-05；M3 评审第 3 条（悬挂模式与自由站立）、第 4 条（JSON 动作文件）。
> 本稿涉及几项对用户可见的约定：动作文件格式、场景文件的新字段、Go2 的控制方式。评审通过后再开发。

## 1. 目标

- 在查看器里**手动**驱动机器人：执行器面板。
- 用**动作文件**驱动机器人：查看器与 Headless 执行同一个文件，轨迹逐位相同。
- 每台参考机器人至少一个预定义动作。
- 越界的目标值、不存在的执行器、格式错误：给出“位置 + 原因”的诊断，沿用场景文件的写法。

## 2. 动作文件（`*.terra-motion.json`）

```json
{
  "format": "terra.motion",
  "version": 1,
  "name": "G1 下蹲再站起",
  "scene": "../../scenes/robots/g1_suspended.terra-scene.json",
  "startKeyframe": "g1/stand",
  "interpolation": "smooth",
  "poses": [
    { "time": 0.0, "targets": { "g1/left_knee_joint": 0.0, "g1/right_knee_joint": 0.0 } },
    { "time": 1.5, "targets": { "g1/left_knee_joint": 1.2, "g1/right_knee_joint": 1.2 } },
    { "time": 3.0, "targets": { "g1/left_knee_joint": 0.0, "g1/right_knee_joint": 0.0 } }
  ]
}
```

**字段说明：**

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `format`、`version` | 是 | 与场景文件相同的约定：未知字段报错，高于支持的版本时提示更新程序 |
| `name` | 否 | 显示名 |
| `scene` | 否 | 推荐的场景文件（相对动作文件）。查看器打开动作文件时，如果当前没有场景，就打开它 |
| `startKeyframe` | 否 | 播放前先按这个关键帧重置；不写则从当前状态开始 |
| `interpolation` | 否 | `step`（保持到下一个点）、`linear`、`smooth`（在点上速度为 0 的三次曲线），默认 `smooth` |
| `poses[]` | 是 | 按时间递增；`time` 单位为秒，从动作开始算；`targets` 为“执行器全名 → 目标值” |

**语义：**
- **单位：**目标值的单位就是执行器控制量的单位，即 M3-02 中的执行器类别：
  - Position：rad 或 m；
  - Velocity：rad/s 或 m/s；
  - Motor：N·m 或 N（乘传动比之前）。
- **插值按执行器各自进行：**某个执行器只在提到它的点之间插值，不要求每个点列出全部执行器。
  - 第一个提到它的点之前保持当前控制量；
  - 最后一个点之后保持最后的值，动作结束后机器人停在最后的姿态。
- **校验（加载时，全部报出）：**
  - 执行器不存在：错误，并列出该实例的执行器；
  - 目标超出控制范围：错误，“越界拒绝”；
  - 时间不递增、为负、不是数值：错误；
  - 执行器类别为 Other：警告，照常执行，但不解释单位。
- **执行方式：**每一步之前按步序号求出目标，交给 `setControl`。
  - 第 k 步的时间取 k × 步长（从动作开始的那一步算起），不看墙钟；
  - 因此与帧率、暂停、单步都无关，查看器与 Headless 的结果逐位相同。
  - 实现上给 `SimulationRunner` 加一个“每步控制器”接口，查看器与 Headless 共用同一个 `MotionPlayer`。

## 3. Go2 的控制方式（评审问题 4）

Menagerie 的 `go2.xml` 用的是**力矩**执行器，关键帧中的控制量只是很小的力矩，播放后会塌下去（M3-02 展示已见）。动作文件需要按关节角驱动它，有两种做法：

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A. Terra 的 PD 控制层**（建议） | 场景文件为指定执行器加 PD 层：动作和面板给出目标角，每步算力矩 τ = kp(q* − q) − kd·q̇，再按控制范围截断后作为力矩控制量。参数取 Menagerie `go2_mjx.xml` 的值：kp 50、kd 0.5 | 通用：以后的力矩型机器人、M5 的策略（通常输出目标角，由 PD 执行）都能用；仍使用原版 `go2.xml` 的物理设置 | 多一层 Terra 代码；PD 按步计算，增益过大时可能不稳定（加载时检查 kd ≥ 0、kp > 0） |
| B. 改用 `go2_mjx.xml` | Menagerie 自带的位置执行器版本，文件已在锁定清单中 | 不写代码 | 它的求解器设置是为 MJX 加速调的（1 次迭代、棱锥摩擦锥、关闭欧拉阻尼），碰撞也做了简化；需要在场景文件中覆盖迭代次数；与 M3-01、M3-03 核查过的模型不是同一个 |

PD 层的场景文件写法（方案 A）：

```json
"controllers": [
  { "type": "pd", "actuators": ["go2/FL_hip", "go2/FL_thigh", "…"], "kp": 50, "kd": 0.5 }
]
```

`actuators` 也可以写 `"go2/*"`，表示该实例的全部执行器。被 PD 层接管的执行器，在面板和动作文件中按“目标角”处理，单位为 rad，范围取关节限位。

## 4. 人形机器人的两种演示（评审问题 3 已定）

- **悬挂模式：**场景文件的模型实例新增 `"fixedBase": true`。组合时删掉该实例根部的自由关节，机器人固定在放置位姿上，可演示手臂和腿的动作，不会倒下。新增场景 `g1_suspended.terra-scene.json`，放在离地 0.3 m 处。
- **自由站立：**沿用 `g1.terra-scene.json`，从 `stand` 关键帧开始，由位置执行器保持。M3-06 记录它能稳定站多久。

## 5. 查看器

- **执行器面板**（窗口菜单中可开关）：
  - 按模型实例分组，每个执行器一行：名字、类别、单位、滑块（范围为控制范围；PD 层接管的为关节限位）、当前目标值、当前力；
  - 拖动滑块即修改目标，滑块本身不允许越界；
  - 动作播放时滑块只读，显示动作给出的目标；
  - 按关键帧重置后，滑块回到关键帧中的控制量。
- **动作菜单：**
  - “打开动作文件…”（程序内文件浏览，只列 `.terra-motion.json`）、“最近打开”；
  - “播放 / 停止”“循环”；
  - 状态栏显示动作名与进度；
  - 诊断沿用场景错误窗口。
- **快照扩充：**为支持面板与 M3-07 的记录，快照新增每个执行器的控制量与输出力，快照修订号 1 → 2。Headless 的输出暂不变，M3-07 再定。

## 6. Headless（M3-05）

- 新增参数 `--motion <动作文件>`，需要与 `--scene` 同时使用。不写 `--duration` 时，默认运行到动作结束后再加 1 秒。
- 输出格式不变。
- 一致性测试：同一场景 + 同一动作，分别用查看器的路径（`SimulationRunner` + `MotionPlayer`，按不规则的帧间隔推进）和 Headless 运行，比较全部实体位姿，要求逐位相同。

## 7. 预定义动作（放在 `assets/motions/<机器人>/`）

| 机器人 | 场景 | 动作 |
| --- | --- | --- |
| G1 | 悬挂 | 挥手（右臂抬起、前臂往复 3 次）；下蹲再站起（髋、膝、踝协同） |
| G1 | 自由站立 | 保持站立 10 秒（用于 M3-06 的稳定性判据） |
| Go2 | 地面（PD 层） | 从 `home` 趴下 → 站起 → 坐下 → 站起 |
| Stretch 3 | 地面 | 前进 1 m → 原地转向 90° → 升降柱升高 → 伸臂 → 张合夹爪 → 收回 |

**关节角的来源：**取各机器人关节限位内的保守值。播放后的效果在可视化验证中由你确认，如果不自然再调整，不追求真实步态。
