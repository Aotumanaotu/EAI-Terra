# EAI Terra 技术决策记录

> 本文记录选择的状态与理由，不记录虚构的实现结果。M0、M1 已全部验收（2026-11-19、2026-11-23）；当前为 M2 阶段，D-102、D-103、D-105、D-106 的初版已于 2026-11-23 评审确定（开发计划 9.5 节）；实际进度见[开发记录](DEVELOPMENT_LOG.md)，变更规则见[文档导航](README.md)。

## 1. 状态与决策规则

- **已确定：**当前开发必须遵守的方向；不表示已经实现或验证。
- **暂定：**有优先候选、可用于原型验证，但尚未形成最终接口或方案。
- **待讨论：**需要明确条件、比较备选并作出选择，不能写成默认已采用。
- **已废弃：**被明确替换的旧方向，保留背景和替代记录。

每条条目包含编号、主题、当前状态、背景原因、选择或备选、影响范围。升级状态时补充确认依据；涉及技术有效性的结论必须关联报告。当前已确定条目的依据为本次明确的项目方向及与其一致的原 README；暂定条目是从原 README 或本轮设计提案提取的候选，均无验证通过证据。

| D-020 渲染数学库 | 已确定，已在视图层使用并验证（M1-07；M1 已验收） | 渲染需要矩阵、投影与四元数运算；与 GLSL 写法一致可减少转换错误 | 使用 **GLM**（仅头文件，MIT）（用户决定，2026-11-19）；**只在 Render 与视图层（`engine/view/`，相机与控制器，M1-07 起）内部使用**，不进入任何公共头文件与 `terra_data` 等公共契约；Terra 双精度位姿在 Render 边界转换为 GPU 所需精度 | Render |
| D-021 OpenGL 最低版本 | 已确定（M1-01，2026-11-19） | 需要在真实 GPU 与软件渲染之间取得共同支持的版本 | **OpenGL 4.5 core profile**，forward-compatible。基线机器：NVIDIA RTX 5060 为 4.6，Xvfb + llvmpipe（Mesa 23.2.1）为 4.5。可用 DSA、`glClipControl`、核心调试输出；不使用 4.6 独有功能（如 SPIR-V），以保持 llvmpipe 可用。见 [M1-01 报告](../validation/M1-01-graphics-env.md) | Render、平台层、测试 |
| D-022 自动化图形测试方式 | 已确定（M1-01，2026-11-19） | 图形测试要能无人值守运行，且结果稳定、不依赖显示器 | **Xvfb + Mesa llvmpipe**，离屏帧缓冲 + 像素回读；单独的 CTest 标签，不阻塞无图形测试（NFR-06）。必须固定 `__GLX_VENDOR_LIBRARY_NAME=mesa`、`LIBGL_ALWAYS_SOFTWARE=1` 并清除 `DISPLAY`，测试断言渲染器为 llvmpipe。真实 GPU 只用于手动运行与帧耗时基线 | 测试、验收脚本、M1-10 |
| D-023 视口相机控制方式 | 已确定，已实现并经用户试用（M1-07；M1 已验收）；**2026-11-19 修订** | 观察机器人与浏览场景需要顺手的视口操作 | **单一组合式控制，不区分模式、不需要切换**（用户试用后修订，2026-11-19）：**按住中键拖动转视角、Shift+中键拖动平移**（第二次修订：右键不顺手；用户考虑过“鼠标直接转视角”但否决，因为会妨碍点击界面，最终选择 Blender 式中键）；W/↑ S/↓ 沿视线方向前后（含俯仰，飞行式）；A/← D/→ 水平左右；E/空格 上升、Q 下降（世界 Z；Ctrl 不再用于下降，留给界面快捷键）；滚轮沿视线拉近/拉远；Shift 加速；F 复位。左键与右键留给界面与以后的选择/拖动物体。只消费 Terra 输入动作（D-018）。**原方案**（同日早些时候）“环绕式与自由飞行式两套控制器、在设置中切换”已被用户否决：纯鼠标的环绕操作不顺手，改为类似游戏的键鼠结合 | 视图层、输入、设置 |
| D-024 编辑器式界面库 | 已确定，已实现并基线验证（M1-13；M1 已验收） | 用户要求参考 Blender、UE5 与游戏的窗口风格：菜单栏、可停靠面板、设置窗口、深色主题 | **Dear ImGui docking 分支**，源码锁定（D-019），MIT（用户决定，2026-11-19）。**不使用 ImGui 官方 GLFW 后端**（它直接接管 GLFW 回调，违反 D-018）：由 Terra 平台层与输入系统向 ImGui 提供事件；“鼠标在面板上时视口不响应”通过动作表优先级与消费实现。渲染后端只在 Render 内部；需要中文字体（来源待定） | UI 外壳、Render、输入、平台 |
| D-025 显示模式 | 已确定，已实现并基线验证（M1-12；M1 已验收） | 用户要求支持全屏，体验像游戏 | **窗口 / 无边框全屏 / 独占全屏**三种，默认窗口；**F11** 在窗口与无边框全屏间切换；独占全屏、分辨率、刷新率、垂直同步、显示器选择放在设置中（用户决定，2026-11-19）。由平台层实现，GLFW 类型不外露 | 平台层、设置 |
| D-026 设置持久化 | 已确定，已实现并经基线验证（M1-14；M1 已验收） | 相机模式、显示模式、按键绑定等需要跨次运行保留 | **JSON 文件**，默认 `~/.config/eai-terra/settings.json`（遵循 `XDG_CONFIG_HOME`），解析库 **nlohmann/json**（仅头文件，MIT，源码锁定）（用户决定，2026-11-19）。读取失败或字段非法时回退默认值并给出诊断，不阻止启动；同时作为动作映射的配置文件格式（关闭开发计划 8.3 待定项）。**M1-14 实现**：nlohmann/json 3.12.0 头文件直接提交（`third_party/nlohmann_json/`，sha256 见 `json.lock`）；`terra_settings` 总是构建，JSON 库不进公共头；内容为界面（语言、缩放、面板、停靠布局）、显示（模式、显示器、独占全屏分辨率、垂直同步、窗口大小）、相机（含视场角）与 9 个操作的按键（主键 + 备用键，Esc 与 Ctrl 保留，同一键只属于一个操作）；单个字段非法只回退该字段，语法错误时坏文件备份为 `.bak`；原子写入；改动 1 秒后自动保存、退出时再保存。鼠标操作暂不可改。见 [M1-14 报告](../validation/M1-14-settings.md) | 设置、输入、应用 |
| D-027 不集成 Filament，参考其 PBR 方法自研 | 已确定（用户 2026-11-19 选择方案 a）；M1-08a 已实现并经基线验证（M1 已验收）；M1-08b（IBL）已实现并经基线验证（M1 已验收） | 用户提出是否集成 Filament（Google，Apache-2.0，v1.81.0）以获得接近 UE5/Blender 的 PBR 画质 | **不集成 Filament**；以其公开的 PBR 文档（BRDF、材质参数、基于图像的光照）为参考，在 Terra Render 中自研 PBR，从 M1-08 材质与光照起增量推进（F-M1-03）。不集成的理由：Linux 构建要求 clang 17+ 与 libc++，与 GCC 11 + libstdc++ 基线（D-008）冲突；它是完整渲染器（自有渲染线程、上下文与材质编译工具链），与 D-004 自研渲染重叠；与 ImGui 和自有 GL 绘制共享上下文复杂。**后备**：若 M3 参考机器人展示中自研 PBR 达不到画质目标，再做一次 Filament 评估原型（含工具链切换成本） | Render、M1-08、F-M1-03、D-004、D-008 |
| D-028 界面字体 | 已确定（用户 2026-11-19），已生成 | Dear ImGui 自带字体没有中文；需要在任何机器上观感一致 | **随项目分发 Noto Sans SC 子集**（SIL OFL 1.1，可自由分发）：来源 Noto CJK 官方 Sans2.004 `18_NotoSansSC.zip`（sha256 锁定），用 `scripts/fonts/make_ui_font.py`（fontTools 4.60.1）裁剪出 Regular 与 Bold：拉丁、常用标点符号、箭头、数学符号、方框绘制、CJK 符号与全角字符、GB2312 全部 6763 个汉字，共 8082 个字符，各约 1.9 MB；输出逐字节可复现；许可文本随字体提交（`assets/fonts/OFL.txt`）。按显示器内容缩放（基线 1.25）调整字号 | UI、assets、许可（D-109） |
| D-029 界面语言 | 已确定（用户 2026-11-19），已实现并经基线验证（M1-13；M1 已验收） | 用户要求中英文都支持 | **中文与英文两种界面语言，在设置中切换**，默认中文；所有界面文字集中在文本目录中按键查找（不在界面代码里写死字符串），测试保证两种语言的键完全一致；切换即时生效 | UI、设置（D-026） |
| D-030 界面缩放与视口导航坐标系 | 已确定（用户 2026-11-19 反馈），已实现并经基线验证 | 4K 显示器全屏时界面文字太小；希望视口有类似 Blender 的三维导航坐标系 | **界面缩放**：默认按显示器推算——系统内容缩放 × max(1, 0.7 × 显示器高度 / 1080)，取 0.05 的倍数（基线 4K、1.25 → 1.75）；Ctrl + 加号 / 减号每次 ±10%，Ctrl+0 恢复自动值；菜单“视图 → 界面缩放”；范围 0.5–4（M1-14 起持久化）。**导航坐标系**：视口左下角，X 红 / Y 绿 / Z 蓝，正方向为带字母的实心圆、负方向为半透明圆，随相机转动并按深度排序绘制，悬停高亮，点击圆点把视角对齐到该轴（从该轴正方向一侧看向前方 5 m 处） | UI、视口、设置（D-026） |
