# M3-06 关节与接触验证

> 状态：**第二次基线运行查明 Stretch 超出限位的原因（模型初始姿态下的自身穿透）；判据改为不计开始后 0.5 s；按用户要求，碰撞几何体改为半透明橙色叠加；待重跑**（2026-11-24，第 4、5 节）。依据：开发计划 10.2 节 M3-06（“每台机器人一组数值判据，写入报告并冻结”）。

## 1. 交付

- **模型描述修订 5：**`EntityDescription::mass`，即实体自身的质量（kg，不含子实体），取自 MuJoCo 的 `body_mass`。用于核对接触力与重量是否平衡，以后 M4 的传感器也会用到。Headless 的输出不变。
- **新测试 `robots.validation`**（需要参考机器人，否则跳过）。全部场景都经“动作 → PD 层 → setControl → step”推进，与查看器、Headless 是同一条路径。

| 场景 | 内容 |
| --- | --- |
| `g1_stand` | G1 地面，动作 `stand_hold`（11 s） |
| `g1_wave`、`g1_squat` | G1 悬挂，两个动作 |
| `go2_hold` | Go2 地面，不给动作，PD 层保持 home（3 s） |
| `go2_motion` | Go2 地面，动作 `lie_stand_sit`（14 s） |
| `stretch` | Stretch 3 地面，动作 `tour`（19 s） |

**每个场景都统计：**
- 关节超出限位的最大量（只看有限位的转动 / 滑动关节）；
- 基座高度的范围、最大倾斜角（基座 z 轴与世界 z 轴的夹角）、水平漂移；
- 最后 1 s 中接触地面的实体；
- 地面接触力合计与总重量之比（取最后 1 s 的平均）。

**模型核查：**步长 0.002 s；重力 (0, 0, −9.81)；转动 / 滑动关节的轴为单位向量；限位区间 min < max；质量非负。

另外两项实测：Stretch 两轮同速时底盘 x 为 0.244 m（正向即前进）；升降柱 9 s 0.593 m、13 s 0.938 m。

**分析：**
1. **Stretch 腕部俯仰超出限位 0.066 rad。**动作 `tour` 没有驱动腕部俯仰，目标一直是 0。能把关节压出限位这么多的，只可能是外力。最可能的原因：升降柱在 0.6 m 时，夹爪的下沿接近桌面（0.48 m）；Stretch 的手臂朝向桌子一侧，前进时夹爪碰到桌沿或桌上的物块。接触力 / 重量只有 0.74，也说明有一部分重量压在桌子上，桌子是静态物体，这部分接触不计入地面。
   - **修改动作：**先把升降柱升到 0.95 m，再开始移动（新时间线：0–1.5 s 升高，2.5–5.5 s 前进，6.5–9.5 s 转向，12–15 s 伸臂、腕部转动与夹爪开合，17 s 收回）。
   - **补充诊断：**出现最大超出量的时刻、关节位置，以及此时所有非地面接触（实体对与法向力），用来确认原因。
   - **检查点：**改为 6 s 时底盘的 x，以及升降柱 0.5 s 与 3 s 的高度（要求升高 0.15 m 以上）。
2. **G1 悬挂下蹲时双脚接触地面，接触力达重量的 1.43 倍。**按腿长估算，悬挂在 1.093 m 时双脚离地约 0.3 m，下蹲只会让脚抬高，原因暂不明确。挥手时没有这种现象。本次只补充诊断：各实体第一次接触地面的时刻，暂不加判据，下次运行后分析。
3. **判据冻结：**
   - **g1_stand：**骨盆高度 0.78–0.80 m，倾斜 ≤ 1°，漂移 ≤ 0.01 m，接触力 / 重量 0.98–1.02；
   - **go2_hold：**机身高度 0.24–0.28 m，倾斜 ≤ 2°，漂移 ≤ 0.05 m，接触力 / 重量 0.98–1.02；
   - **go2_motion：**限位超出 ≤ 0.02（趴下时小腿被压向限位，实测 0.0077）。

## 5. 第二次运行与修改（2026-11-24）

**诊断结果：**
- **Stretch：**最大超出出现在 **0.082 s**，即刚开始时。腕部俯仰到了 0.633 rad（上限 0.56）；此时夹爪本体与手臂第一节（`link_arm_l0`）之间有 1565 N 的接触力，与 D405 相机支架之间有 611 N。
  - **结论：**Menagerie 的 Stretch 在初始姿态（`home` 关键帧只给控制量，位置取模型初值）下，夹爪与手臂连杆互相穿透，开始的几十毫秒里接触力把腕部推出了限位。这与动作无关：先抬升降柱的修改并没有改善，超出量 0.073 与第一次的 0.066 相当。
  - **处理：**开始后 0.5 s 是“初始穿透释放期”，其中的超出只记录、不计入判据，其余时间仍按 ≤ 0.01 判断。这个现象属于模型本身，记录在这里。如果以后需要一个干净的初始姿态，可以在 M4 的资源库中为 Stretch 定义一个经过检验的初始关键帧。Menagerie 的原文件已锁定，不作修改。
- **G1 悬挂下蹲：**双脚在 4.354 s 与 4.364 s 第一次触地，正处于“从下蹲站起”的阶段（3.0–4.5 s）。原因仍不明确，本次在下蹲场景中加了探针：左脚的最低高度与时刻、此时的髋 / 膝 / 踝角度，以及 1 s、3 s 时左脚的高度。
- **Go2 动作：**最大超出 0.0077，出现在 8.536 s，即坐下时后腿小腿被压向限位，没有其他接触，判据 0.02 合适。小腿以外，大腿（1.48 s）与机身（1.678 s）在趴下时触地，符合动作设计。

**用户要求：碰撞几何体以橙色或红色半透明显示。**
- **渲染器：**`Material::opacity` 小于 1 时按半透明绘制：在不透明物体、背景与网格之后，按距离从远到近混合，深度测试、不写深度、不剔除背面，不投射阴影。`FrameStats` 增加 `translucentDrawn`。不透明物体的绘制不变，已有参考图不受影响。
- **场景显示：**“叠加显示碰撞几何体”时，每个参与碰撞的非平面几何体加一个半透明橙色渲染项（线性颜色 (1, 0.28, 0.02)，不透明度 0.45，带少量自发光）。与可见几何体重合时（基本形状的模型常见）呈橙色调。原先的做法是把碰撞几何体按自身颜色不透明地显示出来。地面平面不叠加。
  - **说明：**网格几何体叠加的是显示网格本身，MuJoCo 实际用它的凸包做碰撞，两者略有差别。
- **新参考图 `graphics.render_reference.mjcf_collision`：**材质夹具 + 碰撞叠加，检查 7 个半透明渲染项都被绘制；第一次运行时生成，请查看后提交。
- **变异补充：**“碰撞叠加不是半透明”，变异构建因此改为渲染开启。
